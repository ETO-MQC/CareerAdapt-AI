# 保存反馈与草稿确认修复（2026-10-26）

状态：**PASS（本轮指定 Hotfix 范围）**。相关检查均取得完整退出码，不代表全项目 Release Gate。

## 复现与根因

- 用户反馈教育荣誉点“保存”无反应、顶部仍显示“未保存”，要求检查其他位置。
- 基线 `23f28f1`，工作区干净。修改前 typecheck、2 文件 9 项相关单测通过。
- 匿名样例可复现：两条荣誉合并后点击保存，Repository 已写入，预览也更新，但顶部持续“未保存”。经历表单用 `extraValues` 非空判脏，保存成功后却没有清除这些扩展字段覆盖；再次点击进入“内容相同，无需写入”路径，没有解除脏状态。
- 另一共同问题：父保存方法捕获失败/事实确认后只返回 void，子表单无法区分成功与失败，却无条件清除内部脏标记。保存期间继续编辑时，也缺少提交代次保护。

## 修复范围

1. 文本和结构化保存返回明确 boolean：已写入或同内容确认返回 true；校验失败、不可编辑、存储失败、等待事实确认返回 false。继续使用原保存队列、WorkspaceRepository 与 revision，没有新写入通道。
2. 教育、工作、实习、校园、项目的共用经历表单按编辑代次确认保存。仅成功后确认本次草稿；没有新输入时清理扩展覆盖。有新输入时保留并继续自动保存，旧请求不能清掉新草稿。失败不丢输入，显示内联提示。
3. 经历按钮显示“保存中…／保存／已保存”，已保存时禁用。对事实确认后写入的 canonical 数据做匹配，避免确认成功后仍显示脏状态。
4. 奖项、技能、培训等规范字段表单等待实际成功回执，处理规范化后相同内容的成功确认；失败保留草稿并提供“重试保存”。手动保存期间暂时禁用此表单，避免保存回读重建表单时覆盖新输入。
5. 基本信息保存保留其他文本草稿；清理标准字段/自定义字段时比对提交值，避免旧保存清掉后续输入。文本表单更新草稿时同步最新值，使旧表单“更新草稿后立即保存”可读取本次输入。派生自我评价的保存同样确认并清理对应文本草稿。顶栏聚合仍未保存的文本，不因其他操作成功就误显示全部已保存。
