# 编辑器输入、荣誉组织与排版预设（2026-10-26）

## 用户要求与实现

1. 荣誉输入区占满左右可用空间。根因是经历扩展字段位于两列网格，只对 canonical 网格补过跨列；现同时覆盖 `section-fields-grid-2`。荣誉支持“合并为一段”和“拆分为多条”：合并保留全部条目，以中文分号连接；拆分按分号或换行。操作明确修改当前条目的原 string_list，沿原保存/版本路径进入预览和 PDF，不创建另一套荣誉模型、不自动改写资料库。正常条目内容可合并后重新拆回；原段落的拆分边界由分号/换行决定，不调用 AI 猜测。
2. 排版、样式和页面中的数字输入，先保留编辑草稿，失焦或 Enter 后才校验区间并应用。空值或非法数字恢复已应用值；Escape 可撤销输入。加减按钮直接生效，滑杆继续沿原拖动预览/释放保存行为。改变局部缩放、边距或滑杆旁数值都复用同一确认输入控件。
3. 政治面貌沿 Resume Schema v2 的 `basics.customFields` 存储，字段标签为“政治面貌”、标记 sensitive，七模板的共享头部均可显示，无需为每个模板另建事实字段。AI 映射提示明确要求源值、字段路径和证据；本地识别只读取抬头中的明确政治身份词，未填写则不生成，不从“群众服务中心”等词推断身份。来源回补保留块/range，必须经新增个人信息确认后才允许入正式分支。既有明确字段不会重复回补。默认排在邮箱后；已有用户排序保持优先。
4. 模板页下方增加“排版预设”。内置截图数值：15px、1.56 行距、0 字距、10px 栏目间距，姓名 1.55、板块标题 1.08、联系方式 0.94，其余截图局部比例为 1。用户可命名保存当前排版并在其他简历应用/删除。预设只含字体、排版/间距、颜色和 precision；不保存简历内容、人物、分支、模板 ID、栏目顺序、可见性或照片数据。数据由 WorkspaceRepository 原子写入原有 appMeta，无新表/依赖。
5. 板块、条目、荣誉行与个人信息排序统一手柄指针捕获。拖动超过相邻条目中点，显示新的视觉顺序；源位置保留约 50% 透明占位，浮动行约 50% 透明，相邻项通过 180ms FLIP 滑动，尊重系统减少动态效果偏好。移动只预览；松手在有效区域一次提交，移出后松手、Escape 或指针取消则回退。原上下按钮与 Alt+方向键保留，手柄支持触屏，边缘可滚动。

## 关键决策与边界

- 基线 `c7152f6`，开始时工作区干净。复用 Repository、Schema v2 和原展示队列；没有改 Fact Guard，没有隐式写回个人资料库。
