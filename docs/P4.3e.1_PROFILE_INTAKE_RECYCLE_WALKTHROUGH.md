# P4.3e.1 Profile Intake / Recycle Isolation Walkthrough

This walkthrough uses the disposable Playwright context and the supported Profile UI. It does not write IndexedDB directly and does not use a real user profile.

## Automated supported path

Run the exact regression with:

```powershell
pnpm exec playwright test tests/e2e/p43e1-profile-intake-recycle.spec.ts --project=chromium --workers=1
```

The bootstrap performs these UI actions:

1. Open `/profile`.
2. Create the disposable person `P43e1 Disposable`.
3. Add an education item with synthetic values: `P43e1 Example University`, `Bachelor`, `Example Major`, `2024-09` to `2028-06`.
4. Move that item to the recycle bin and reload the Profile page.
5. Start a fresh Agent session with the Profile Intake request.
6. Confirm that the recycled education is absent from the active Profile read.
7. Send the regression meta-question and verify a fresh `get_profile` read, no intake capture, and no Profile mutation.
8. Send the typed education narrative, open the `经历核对` artifact, verify the typed fields, and choose `采用`.
9. Send `完成整理`, choose `仅保存资料库`, confirm the repository write, and verify the new canonical education item.
10. Repeat the disposable flow and choose `生成一份通用简历`; confirm Profile commit and General Resume generation.

## Diagnostic fields to record

For each run, record only IDs, versions, kinds, and tool names—not personal text:

| Checkpoint | Capture |
| --- | --- |
| Before recycle | `profileId`, Profile version, active canonical item IDs |
| After recycle and reload | Profile version, active canonical item IDs, recycle item IDs |
| Meta-question turn | current-turn tool names; expected `get_profile` only among domain actions |
| After typed narrative | `TaskState.stage`, `latestIntakeSource.sourceKind`, source `turnId` and `messageId` |
| After candidate decision | intake draft revision and candidate ID |
| After save-only | Profile version, active canonical item IDs, recycle item IDs, `TaskState.stage` |
| After General Resume | `TaskState.stage`, `generalResumeResult`, generated resume/revision IDs |

Expected invariants:

- The recycled canonical education ID is absent from every active `get_profile` result.
- The meta-question remains a side turn with `rootGoal=profile_intake`; it never creates `latestIntakeSource`, calls `capture_profile_intake`, or mutates Profile state.
- The typed narrative creates `latestIntakeSource.sourceKind=career_narrative` and a required typed `structuredItem`.
- The restored item, when tested separately, reappears exactly once; recycling it again removes it from the next fresh read.

The committed fixture is anonymized at `tests/fixtures/p43e1-profile-state-regression.json`. The browser bootstrap remains UI-only; IndexedDB access in the test is read-only diagnostics.

## Sixteen-step local manual walkthrough

1. In a disposable Playwright context, open `/profile` and create `P43e1 Disposable`.
2. Record the selected `profileId` and Profile version before adding the test item.
3. Add the synthetic education item through the Profile UI.
4. Record the active canonical item ID and the new Profile version.
5. Move that education item to the recycle bin through the Profile UI.
6. Reload `/profile`; record the Profile version after recycle and confirm the active canonical ID list excludes the item.
7. Start a fresh Agent session with the Profile Intake request.
8. Confirm the assistant does not mention the recycled education item before a current Profile read establishes it.
9. Send the exact recycle-bin meta-question from the regression fixture.
10. Record the current-turn tool names and TaskState; expect a fresh `get_profile`, zero capture/mutation tools, and unchanged `rootGoal=profile_intake`.
11. Open `/recycle`, restore the synthetic education item, and return to `/profile`.
12. Perform a fresh Profile read and record that the same canonical ID appears exactly once.
13. Move the restored item to the recycle bin again.
14. Reload and perform another fresh Profile read; record that the canonical ID is absent again and the recycle item ID remains available for restore.
15. In a new intake turn, enter an anonymized education narrative, verify `school`, `degree`, `major`, `startDate`, and `endDate` in the typed artifact, choose `采用`, then choose `仅保存资料库` and confirm.
16. Verify the saved canonical fields and Profile version, then choose `生成一份通用简历`, confirm the required writes, and record `resume_ready` plus the generated resume/revision IDs.
