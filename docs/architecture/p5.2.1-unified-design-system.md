# P5.2.1 — CareerAdapt Unified Design System

状态：**设计提案 + 隔离原型已实现**；生产迁移未实施。2026-11-03。以 `src/styles/product-tokens.css` 与 `src/components/ui/product/index.tsx` 为现有事实来源，不能把本规范新增 API 当作现有公开 API。

## 1. 令牌分层与所有权

```text
Hermes applied Theme Tokens（Host 单一权威）
  → .careeradapt-ui 内 --ca-* Semantic Tokens
    → Product components（presentation only）
      → 各业务页面的信息架构

Resume snapshot → --resume-* → A4/print/PDF（独立支路）
```

原型是独立根，读取现有 --product-* 并把 :root selector 局部化为 .prototype，不改生产样式。正式 Host 适配将局部 --product-* 映射到 --ca-*，不在 document root 再维护一套全局 theme 状态。

| 固定 Host token | Career 语义 | 现有 Product token | 消费场景 |
| --- | --- | --- | --- |
| --ui-text-primary / --dt-foreground | --ca-text | --product-text | 标题、正文、控件 |
| --ui-text-secondary / --dt-muted-foreground | --ca-text-muted | --product-text-secondary | 说明、时间、元数据 |
| --ui-bg-editor / --dt-background | --ca-canvas | --product-app-bg | 页面画布 |
| --ui-bg-elevated / --dt-card | --ca-surface-raised | --product-surface-elevated | 输入器、菜单、浮层 |
| --dt-card | --ca-surface | --product-surface | 业务面板 |
| --dt-muted | --ca-surface-subtle | --product-surface-subtle | 选中附近、摘要条 |
| --ui-stroke-secondary / --dt-border | --ca-border | --product-border | 分组/边界 |
| --dt-primary / --dt-primary-foreground | --ca-action / --ca-on-action | --product-accent / --product-accent-ink | 主操作（品牌主题获批后全局协调） |
| --dt-ring | --ca-focus | 原 focus 使用 --product-accent | 键盘焦点 |
| --dt-font-sans / --dt-font-mono | --ca-font-ui / --ca-font-code | 现有系统 UI 栈 / 系统等宽栈 | 界面与技术字段 |
| Host 无完整职业语义集合 | --ca-danger/warning/success/info | 现有 danger/warning/success；info 待定义 | 状态明确文字说明，不能推断事实 |

Host tokens 的存在以锁定 styles/theme 源码为依据，不把其 CSS 命名视为永久 SDK 稳定承诺。后续补契约快照；缺 token 时使用审核过的本地语义值，不探测内部模块/私有设置。Host theme 改变后业务正文/面板随之变化；Career accent 在任意第三方 Host palette 下的协调仍需视觉验收。不要把当前原型的局部主题按钮移植成生产全局主题 setter。

## 2. Design Tokens

### Color

沿用现有 light/dark 全套值，详细值见[审计色表](p5.2.1-unified-experience-design-audit.md)。浅主色#176b5b、深主色#72d58b；画布#f3f6f4/#0d1214；面板#fbfcfb/#141a1d；正文#18201b/#eef4f0。surface 与 raised 只作结构分层，不用嵌套阴影堆出层级。

文本对比目标：常规正文4.5:1、大字/非文本状态边界3:1；主文本、辅助、on-action、warning/错误在当前两个基础主题中验证；任意第三方主题不视为自动达标。禁用控件既有 opacity .5 保留，但不把关键结果放进禁用态。状态同时有图标/文案，不以绿/红判事实真假。选中项使用 accent 约10%背景+文字加重，不给整屏涂色。品牌绿不覆盖 Resume 模板强调色。

### Typography

| 层级 | 规格 | 使用 |
| --- | --- | --- |
| Page title | 18px/1.3，650；原型局部21px待用户选 | 常规业务页标题，最多1个主标题 |
| Section title | 15px/1.4，650 | 面板标题 |
| Body | 14px/1.55，400 | 表单、长正文 |
| Chat body | 14px/1.75–1.85 | 阅读；原型紧凑演示13px，不强制生产降字号 |
| Caption | 12px/1.45 | 解释与来源 |
| Label | 12px/1.4，600 | 字段与控件标签 |
| Minor metadata | 11px/1.5（规范下限建议） | 时间、状态，禁止用于关键错误 |
| Code | 12–13px/1.6，系统等宽 | 工具参数、路径，局部横向滚动 |

原型部分次要元数据9–10px用于密度比较，**不是批准生产小字标准**；P5.2.2需放大至至少11px并在1024检查。中文需真实 Windows 字体复查，截图不能认证所有系统渲染。

### Spacing / Radius / Shadow / Border

- spacing 基础4px，允许4/8/12/16/20/24/32；页面24、窄屏20，控件内边距12；面板 normal16、compact12、spacious20。不要每页重设同类卡片padding。
- radius：control8、surface12、dialog16、badge pill；文档纸面0。原有24保留可用，当前不作为默认大卡圆角。
- shadow：surface默认none；raised仅subtle；Dialog/Dropdown用floating。Modal backdrop 与产物布局不是同一种分层。
- border：1px、语义 border；hover可用 strong；focus2px outline、offset2px。不要用粗实线强调所有 section。

### Motion / Z-index / Layout

颜色与边框160ms；展开/收起120–160ms；不对主工作区做重动画；拖动直接跟指针。尊重 prefers-reduced-motion，停动画后状态仍可读。streaming不主动抢滚动，用户上翻后保留位置，提供返回底部按钮（正式实现待做）。

局部层级：base0、sticky10、menu30、tooltip40；modal用原生 top layer（不用大z-index抢占Host）；Host popover层级遵守Host，插件不得注入全屏最高层纸纹。产物 pane 与 chat 同一层，不以 fixed/portal 浮在聊天上。

几何：Header56；Sidebar216（原型）/64 rail；业务页边距24；Conversation阅读最大720；Artifact默认40%、可调34–50%、min320；分隔命中区9px、可见线2px。正式布局还需按容器宽度同时约束聊天min420、产物min320，不能只以百分比保护。对话工具栏、输入区和页头固定在各自flex流，消息与产物分别min-height:0/overflow:auto。

### 响应式

- 1920：保留阅读最大宽度；产物约669px，不无限拉长聊天正文；页头和输入器对齐。
- 1440：导航216，chat约706、产物约477；可拖到34–50%，默认并排，无遮罩。
- 1024：导航64，chat约555、产物约376；按钮保留label/tooltip语义，模型控制紧凑；可手动关产物让聊天占满，并显式恢复。Profile 132/206/剩余列，基础字段单列；不缩放整张页面。
- <760原型实验：上下独立分区，不默认遮罩；9px竖向separator失去拖动能力，不属桌面验收。正式移动策略需单独设计，不声称已完成移动适配。

### 任务与产物状态（设计 DTO，不改变 Domain）

正式展示需关联 sessionId/taskId/artifactId/revision/status，状态来自Host实际事件，不凭“有文本”推断成功。loading显示已知状态；complete保留来源与待审核；failed保留旧内容并标记；cancelled不标完成；换session不得沿用上一任务产物。迟到事件只能更新匹配的task/revision，右栏崩溃不得中断运行/发送/停止。此契约待获准后接入，不在本轮创造Domain API或确认凭据。

## 5. 各业务页面保持各自结构

Profile：人物/版本摘要 → 分类 → 条目 → 详情，唯一编辑权仍走Repository；原型只读合成snapshot。Jobs：岗位列表 → 条件关系/来源/核对，不能把所有条件平铺成聊天。Applications：阶段/状态 → 申请记录/材料/活动，需明确下一行动。Resume Studio：编辑导航 → 结构化字段 → 真白A4，样式检查器与消息不能污染纸面。Career Settings：职业偏好/业务设置；Provider、权限、Host主题继续到Host设置。

## 6. 验收标准

生产阶段必须覆盖组件尺寸一致、contrast、keyboard、IME、long code与长文件名、空/加载/失败、light/dark/system、1024/1440/1920、高缩放、pane拖动/收起/恢复、跨任务迟到与错误隔离；同步审查现有入口未删除。凡会触碰屏幕预览主题，补同snapshot的A4内容/字体/分页/打印/PDF一致性。没有这些证据时不宣告生产设计系统完成。
