## 2. 真实根因与设计原则

原有活动已按 Turn 分组，但展开状态由 localStorage 的旧开关决定，运行时默认收起；没有耗时投影。`toolStatus` 对带 activityState 的活动直接展示 content，可能包含工具名、错误和内部内容。业务状态独立位于对话顶部，和具体轮次脱离。Markdown 已有 H1–H6、表格与引用支持，本轮补语义提示块和字重层级，不重复建设解析器。

新组件只读取消息、当前 businessWorkflowProgress、activeTurn、turnCheckpoints 与 hermesRun。业务回执仍为完成/正式保存的权威来源；模型结束与业务完成分开，Host 回执未返回时继续显示处理中。已核验恢复优先于同轮早期失败，早期步骤仍可展开查看。

## 4. 过程展示状态机 / 映射规则

| 展示状态 | 数据依据 | 默认展开 | 摘要/图标 |
|---|---|---|---|
| running | submitted / processing / committing；含模型结束但 Host 回执仍待核对 | 是 | 当前业务标签、实时耗时、轻呼吸与旋转图标 |
| waiting | awaiting_input / awaiting_review / awaiting_confirmation | 否 | 补充/审核/确认标签、中性时钟 |
| complete | 现有投影已核验完成，或历史步骤正常结束 | 否 | 已保存/已完成步骤；普通对话显示本轮回复已结束 |
| failed | failed / blocked / partial，或无权威投影时的失败消息 | 否 | 原业务失败性质与恢复说明 |
| cancelled | 现有取消投影或中断标记 | 否 | 已取消、中性停止图标 |

阶段变化时重置默认展开状态，同阶段活动刷新保留手动开关；详情仍支持原“查看任务步骤”和原生键盘操作。每轮只展示一张过程卡片，当前轮状态不污染历史轮。

计时优先 activeTurn.startedAt/completedAt，再用持久 turnCheckpoints 和相应 Run 最后事件。没有终止时间证据的旧消息使用消息时间估算，并明确写“用时约”；不新增计时持久化。超过一分钟显示分/秒。运行每秒刷新，结束取消定时器。reduced-motion 关闭呼吸/旋转/思考点动画。

## 5. 业务文案与工具文案映射

| 数据/工具族 | 用户步骤文案 |
|---|---|
| 无工具的运行轮次 | 正在思考 / 正在处理当前任务 |
| workflow.job_intake | 整理岗位信息并核对保存结果 |
| job.parse / parse_job_description | 分析岗位要求 |
| job.list / list_jobs | 检查是否已有相同岗位 |
| job.commit / commit_job | 保存岗位；有 businessCommitted 回执才显示已保存 |
| profile.get / profile.active / profile.list | 读取资料库 |
| material_intake / material.prepare | 读取并整理材料 / 准备材料审核 |
| profile_intake_turn / finalize | 整理个人经历 / 准备资料审核 |
| workflow.tailor_resume | 准备岗位简历优化（不把选择来源误称为提案已生成） |
| workflow.compose_resume | 生成通用简历提案 |
| resume.apply_precise_edit / preview.apply_changes | 保存已确认的修改 |
| resume_export / export.resume | 准备预览或导出 |
| 未知工具 | 处理当前任务 |

默认不取活动 content、input、JSON、operationId 或 raw tool name 作为步骤文本；展开只显示业务动作和执行状态。原始诊断保留在现有开发诊断能力中。不是展示原始 chain-of-thought，也不生成伪造的内部思考。
