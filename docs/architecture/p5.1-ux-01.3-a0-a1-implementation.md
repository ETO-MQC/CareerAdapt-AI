## 2. A0 最终契约与可信边界

模型入口 `career.workflow.precise_edit` 严格只接受 `{ proposedValue: string }`，unknown 字段拒绝。它是 READ 提案入口，不具备正式提交权限；目标必须先由用户在现有 Agent 工作区明确选择。新增内部 prepare/apply 工具复用 Gateway；apply 为既有 user_confirmation 策略，模型生产面不暴露该原子写工具。Hermes Facade 目录从9项增为10项，原有4项小读取面不扩张；未修改模型/进程默认值或已有工具权限。

| 提案字段 | 实际来源及验证 |
|---|---|
| schemaVersion | precise-edit-v1 |
| selection.sessionId / taskId | Host Session ID / Host 生成的精确编辑任务 nonce |
| selection.profileId | Session 明确绑定 Profile，必须等于 Branch.profileId |
| selection.branchId / baseRevisionId | 用户显式选择的 Branch / 当前 Revision；历史版本只读 |
| selection.sectionType / itemId | project/work/internship；真实 structuredContentItems 外层条目 ID |
| selection.field / bulletIndex | description + null，或 highlights + 范围内非负整数 |
| turnId | Host 的实际提案 Turn，模型不传 |
| profileVersion | Repository 回读的 Profile.version，首次提交严格相等 |
| branchPurpose / jobId | 实际 Branch；general 不带 jobId，job_specific 必须一致 |
| baseBranchRevision | 实际 Branch.revision，用于 CAS |
| canonicalFieldId | 复用目录 section.field；不另造字段身份 |
| originalValue / proposedValue | 当前字段精确原字符串 / 唯一模型或用户建议输入；都必须非空白 |
| evidenceRefs | Domain 从所选条目的既有 factRefs 经 resolveBranchFactRefs 解析；仅已确认事实，无模型引用 |
| claimClassification | 仅在原 Guard 与 Claim Safety 通过后产生 presentation_only；不接受模型分类 |
| operationId | 可信层生成 precise-UUID，确认全过程固定 |
| proposalHash | SHA-256，覆盖上表全部内容及 operationId，自身除外 |

条目外层 ID 和 data.id 在现有架构中可能不同，分别为简历条目与 canonical item 身份；首个原型误要求二者相等，已纠正为按真实外层 ID+section 唯一定位，不重写原身份。

哈希使用递归对象键 Unicode 码元序、保留数组次序、UTF-8 JSON；不 trim 正文，不依赖 UI/时间。拒绝 undefined/非有限数等非 JSON 值。字段、目标、Session/Task/Turn、原值、新值、证据、版本或 operationId 任一变化都会改变身份。hash 不表示用户同意。

可信分类使用既有 runRuleFactGuard 与 validateEachTailoringDiffLocally；并以原字段本身运行既有 Guard 的措辞约束，禁止把“其他已确认事实中存在”的新指标/技能悄悄追加到本字段。没有放宽阈值。新事实、责任升级、成果数字等拒绝，不在 A1 新建事实确认流。

## 3. 持久化：唯一权威与 before/after

| 路径 | Before | 本轮 After |
|---|---|---|
| taskState.knownSlots.preciseResumeEdit | 无 | `{ selection, proposal?, outcome?, decision? }`，**唯一完整可执行提案来源** |
| activeTurn.workflowCheckpoint.preciseEditRef | 无 | `{ operationId, proposalHash }`，不存完整副本 |
| pendingConfirmation.validatedInput | 原流程自有内容 | 精确编辑时仅同一引用 |
| pendingToolCall.input | 原流程自有内容 | 精确编辑时仅同一引用 |
| pendingConfirmation.status | 既有 pending/confirmed/rejected | 复用；明确点击后先持久化 confirmed，再进入写入 |
| taskState.knownSlots.preciseResumeEditFailure | 无 | 原工具错误投影，失败保留原提案 |
| preciseResumeEdit.outcome | 无 | Repository 权威 `{ operationId, proposalHash, branchId, revisionId }` |

没有新增 dependencyExpectation 字段语义，也没有重用 resumeHash。原四处完整副本方案改为一个完整提案加三处引用，符合用户优先单点存储的约束。上述均在既有开放 record 容器中，顶层 Session/Task Schema 不改。提案传输结果只用于投影，不作为第二个恢复 authority。

确认/恢复/首次提交检查提案 hash、Session/Profile、任务 nonce、实际 Turn、三个引用以及两处 operationId/toolName/turnId；不一致直接拒绝，不选择某份继续。拒绝/取消持久化既有 cancelled 终态并清除 pending 引用；成功清除已消费 pending 引用，保留单点提案及权威回执。相同提案的迟到/重复工具回执不能重置确认，也不能复活拒绝/取消。错误 Session/Turn 不能投影，后台结果不能替换当前 Session。

旧会话无此 slot，行为不变；不从旧 compose/tailoring 提案转换。未知版本/缺字段失败关闭，不默认补齐。代码回退后不保证旧客户端可继续尚未确认的新提案，但正式 Revision 仍是原 Schema，可被旧正式读取路径识别。

## 4. operationId、索引与原子写入

- AgentToolResult/Message/Confirmation/PendingToolCall 的 operationId 上限160；Revision/BranchOperation operationId 为 min(1) 无 max；Entity ID 无导致137字符不兼容的上限。
- 内部账本 key 为 `precise:<SHA256(original operationId)>:<proposalHash>`，**137 ASCII字符**。原用户操作 ID 保留在完整提案；Response 使用原 ID。
- 现有 `resumeBranchOperations` 为 `id, &operationId, ...`，未改版本或索引。真实 Dexie/fake-indexeddb 集成验证 startsWith、唯一性及并发事务。
- WebCrypto 两次哈希均在开启 IndexedDB 事务前完成。
- 一个 rw 事务覆盖 profiles、jobDescriptions、resumeBranches、resumeRevisions、resumeBranchOperations、agentSessions。前缀检查与写入串行原子；同原操作ID不同hash直接冲突。
- 无旧回执时核对已持久化明确确认、Profile严格版本、Branch/purpose/job、当前Revision/CAS、原值、可信证据和 Guard；在可信层复制 highlights 并仅改一个 index；复用 **createResumeRevision**，更新 Branch 指针并存原账本回执。
- 已有相同key回执时返回其历史 Revision，不要求 Branch 当前指针仍指向它，也不把历史回读当作新的写入；Profile 严格版本约束适用于新提交，不阻断已提交历史回执的只读恢复。
- 不修改 mutateResumeBranch、applyTailoringDiffs 或通用 AgentExecutor 的缓存/幂等语义。

提交后 TaskState 持久化失败：原确认已落盘，刷新/显式恢复只查询 Repository 回执，读回原 revisionId，不再写入。没有回执的恢复不自动重试；只有显式重试才尝试原提案，并再次做 CAS。过期提案失败保留，允许明确取消后重新选择当前版本；不自动 rebase。

## 5. A1 实际能力与守恒

支持且仅支持：project.description、project.highlights[index]、work.description、work.highlights[index]、internship.description、internship.highlights[index]。必须是已选择的当前 Branch/Revision，已有非空字段、有效来源、有效索引和非空白新文本。

目录复用 resumeFieldById，精确选择 Schema 和 UI 单独限制六组合；不修改一般 Field Catalog 来冒称其他 section 可提交。不存在/空字段、历史版本、越界、原值不符、无确认来源、Profile变化、分支身份/岗位不符都拒绝。标题、日期、技能新增、结构删除/重排、其他 section、历史Revision编辑均不支持。

对目标正文之外的完整补集做深相等断言。唯一同步更新的是所选条目的既有 legacyTextProjection 与 contentItems.text 正文镜像，以及必需的 Branch revision/currentRevisionId/updatedAt 和新 Revision/操作回执；其他正文字段、条目和顺序、Profile、非目标通用/岗位分支、source/factRefs/已确认元数据完全不变。

持久化展示配置保持原样；读取展示配置时派生的 contentRevision 指针随正文版本更新，不能把该指针变化误报为模板变化。测试同时断言完整样式设置相等及 appMeta 原记录不变。
