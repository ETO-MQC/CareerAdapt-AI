## 2. Career Context Contract

`career.context.retrieve` 继续只读。查询参数为 profileId、query、intent、可选 jobId/resumeId/targetText、maxFacts（1～24，默认 12）。新增 intent：profile_enrichment、resume_composition、resume_tailoring、resume_review。

返回：

- `binding`：personId（旧数据可缺）、profileId/profileRevision、selected resumeId/branchId/resumeRevision/revisionId、jobId/jobVersion。
- `facts`：已确认事实、实体 ID、statement、source references、confidence、maturity、relevanceReason；按查询和任务限制数量。
- `pendingFacts`：受限的未确认/高风险事实 ID 与状态，不将这些内容混入可用事实。
- `materialSources`：本次返回事实的 sourceId → factIds 引用，包含 provenance 来源，不仅限于 evidence 文件表。
- `sourceSummary` / `careerContextResultSummary`：版本、检索覆盖和数量；不包含全量正文。
- `workflowCheckpoint`：由 Gateway 注入的 Host workflowId/stage；不是模型提供的可写 authority。
- `unsupportedClaims`：没有找到支持的信号，不能解释成“不具备”。

Profile enrichment / Fit / Tailoring / Review 使用相关性过滤；Composition 保留所选 Profile 的有界事实集合。完整所选正文和分析由原 workflow 内部读取，不默认从检索工具返回完整 Profile、所有 Resume、所有 Job、所有附件或历史 tool result。待确认内容始终不进入已确认 facts。

Gateway 在请求省略目标且 Host task 与当前 Profile 一致时补入所选 Resume/Job ID。不同 Profile 的任务不能供应默认目标。

跨 Run 新增 `careerCheckpoint`：从 Host taskState 白名单提取 workflow/stage 和所选 profile/resume/source/job ID、revision，不序列化 knownSlots、完整 facts 或旧工具输出。HTTP Schema 拒绝额外字段，官方 Hermes 请求在 career_context 与 instructions 中携带该轻量投影。它是检索定位信息，不能授权写入或绕过重新读版本。此传输已通过本轮 HTTP/单元测试；**尚未取得最后改动后的真实 Hermes 浏览器复验**。

Memory 边界已加入实际 Run instructions 与 Skills README：事实归 Profile/Repository，任务状态归 Session/checkpoint，方法归 Skills；长期 Memory 仅用于稳定轻量偏好，不保存完整简历、JD、附件或未确认推断。

## 3. Requirement → Evidence Contract

新增的是派生 `candidate-evidence-matrix-1`，不是第二套 Job/Profile/Resume，也没有新表。

```text
binding = profileId + profileRevision
        + resumeId + resumeRevision + revisionId
        + jobId + jobVersion + graphHash
analysisId = hash(ruleVersion + binding + canonical requirements + candidate evidence)
```

每行包含 requirementId、rawSourceRef、normalizedRequirement、priority、AND/OR groups、evidenceStatus、candidateFactIds、sourceIds、evidenceUnitIds、confidence、unresolvedAmbiguity、rationale。

状态契约：direct、transferable、partial、unknown、conflicting、mismatch。当前保守规则复用已有 matcher：direct → direct，strong_transferable → transferable，partial → partial，其余 → unknown。**本轮没有实现通用语义矛盾检测；不会凭未提及就生成 mismatch/conflicting。** JD 永远不作为候选事实来源。

已有 JobRequirementGraphV4 保留原始 requirement IDs、sourceSpan 和组关系；V2 matcher 只做原图的兼容投影，不重解析已保存的 JD。旧 Job 没有持久化 graph 时仍沿用原兼容路径，不伪称全部旧数据已迁移到 V4。

`CareerIntelligenceCache` 由 BrowserAgentToolService 持有，最多 16 项，绑定规则版本、实体版本与输入指纹；返回副本，防止调用方修改缓存。Fit 与 createTailoringSession 共用同一个分析入口；Composition 也使用该入口。跨页面/进程重建缓存仍可从持久化图确定性重建，**不承诺缓存跨进程持久化，也不承诺只增量计算受影响行**。

## 4. Tailoring 数据流

```text
saved JobRequirementGraphV4
  → canonical projection + confirmed candidate evidence
  → version-bound CandidateEvidenceMatrix
  → TailoringSession / selected CompositionCheckpoint
  → relevant evidence rows for each writer field
  → existing Writer + Fact Guard
  → existing Reviewer / per-field accept-edit-reject
  → expected Profile + Job + source Resume revision checks
  → WorkspaceRepository isolated branch/revision
  → existing Preview/PDF renderer
```

逐字段写作的严格 Task Schema 和实际 prompt 都带 requirementEvidence（analysisId + 相关行），避免新增字段被 Schema/prompt 丢掉；Composition Writer 的严格输入与 prompt 同步接线。Reviewer 保留 analysisId。未支持的要求可在评审结果中作为 `withheld` 返回；不强制生成一条改写。

原 diff 已携带 target、original/value、requirementIds、evidenceRefs、reason、supportLevel；沿用原核对和确认。通用 Resume / Profile 不被定向提交覆盖。没有修改 Fact Guard 阈值、事实确认语义或 PDF renderer。

## 5. Reviewer / Score 定义

1. **Job Fit**：mustHaveCoverage、preferredCoverage（total/direct/unknown）、逐项 evidenceStrength、materialGaps、unknowns；引用 ruleVersion。原数字覆盖分仍来自 `job-evidence-coverage.v2.0`，不改变其权重，不将其解释为面试概率。AND/OR 原组关系随 Matrix 保留，新增摘要不是经过校准的整组满足概率。
2. **Content Quality**：factual fidelity、specificity、relevance、clarity、evidence density、redundancy、ownership accuracy；`resume-diagnostics-1` 返回 pass / needs_review / unknown 与可检查原因，不制造总分。
3. **ATS/Structure**：text extractability、section structure、field completeness、reading order、supported keyword coverage、unsupported keyword injection。前两项真实渲染相关结论（提取性/阅读顺序）在未检查实际产物时保持 unknown。

Hard gate 检查实际 emitted claim 的 classification 与 Fact Guard 状态；UNSUPPORTED、NEEDS_USER_CONFIRMATION 或 guard 未通过不能被语言指标抵消。未发出的 withheld claim 不等于简历中有伪造。ownership 的语义检查继续复用 Writer/Reviewer，独立诊断未校准时返回 unknown。stale/wrong-target write 由 Gateway / Facade / Repository 拒绝，而非以扣分代替拒绝。
