# P5.2.0-B2-B1 Runtime Release Decision

2026-11-02. **BLOCKED for production release approval**. Research complete within scope; no production runtime is approved. No dependency was installed, no Career database was opened, and no runtime upgrade or package was produced.

## Evidence and maintenance

Local independent Node reports 24.15.0. The exact [Node 24.15.0 SQLite documentation](https://nodejs.org/download/release/v24.15.0/docs/api/sqlite.html) identifies node:sqlite as Stability 1.2 / Release candidate. Node major-version LTS does not make every module stable; [Node release policy](https://nodejs.org/en/about/previous-releases) recommends supported LTS for production. Prior B1/B2-A transaction/CAS/crash/parity results remain historical evidence, not new release certification.

The actual existing Hermes Python executable reports CPython 3.11.13, SQLite library 3.47.1, Windows AMD64. This task imports sqlite3 only for version metadata; it creates no Python SQLite connection. [Python's maintenance table](https://devguide.python.org/versions/) lists 3.11 as security-only, end of life October 2027. A maintained language series does not certify that this exact older patch/build has current security fixes. Bundled Hermes Python is a PoC execution environment, not a CareerAdapt-owned release pin. [Python sqlite3](https://docs.python.org/3.11/library/sqlite3.html) is a documented DB-API implementation with transactions and online backup support; API maturity does not certify canonical TypeScript domain parity.

[Rust stable channels](https://doc.rust-lang.org/book/appendix-07-nightly-rust.html) provide a stable language release path. [Go compatibility](https://go.dev/doc/go1compat) describes source compatibility; [Go maintenance policy](https://go.dev/doc/devel/release) supports a major until two newer majors exist. Neither language alone supplies the selected SQLite binding, canonical Career domain implementation or a signed application artifact. Rust/Go compilers, drivers and binaries were not installed or probed.

## Recommendation and decision

Retain independent Node as the first research candidate because it can reuse canonical TypeScript business rules; this is an engineering recommendation, not a release approval. Resolve the exact maintained Node/SQLite combination and RC policy before shipment. If no acceptable built-in API/maintenance combination is approved, stop and request a separately scoped dependency/runtime decision; this task installs nothing. Python is useful for the verified Hermes broker and remains a possible independently owned service runtime, but is not selected simply because Hermes already supplies Python. Rust/Go remain alternatives only after explicit cost/driver/parity evaluation; no rewrite is authorized.

Even a fully qualified runtime cannot repair the missing trusted Host confirmation or Renderer-disable revocation. Releasing a write-capable Domain Service is NO-GO under this gate. Before any later production authorization: pin/hash/license a supported runtime and engine per platform; prove canonical rule parity, unique ownership, backup/restore, compatible updates, crash/orphan/unknown-outcome handling and independent confirmation. No further stage is started.
