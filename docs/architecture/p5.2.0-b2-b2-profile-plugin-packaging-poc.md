## B. Profile audit and architecture

Audit preceded implementation. Existing entry `src/app/profile/page.tsx` mounts `ProfileWorkspace.tsx`. The latter creates `new WorkspaceRepository()` at module scope, uses `useWorkspace(repository)`, AI intake, PDF/export, archive/restore, canonical write contracts, structured experience/project forms, product topbar and CareerContextEntryBar. It owns window context-change listeners, timeout/debounce and download URL lifecycle. Next routing/AppShell/context and transitive persistence are product responsibilities, not suitable plugin imports. Direct page hooks `useRouter/useSearchParams` are not present; their absence does not make the business view portable.

| Class | Existing components/rules | This PoC |
| --- | --- | --- |
| A: pure display | Earlier A `ProfileCareerView`, scoped profile.css, canonical display DTO shape | Reuse view and stylesheet unchanged; all seven sections rendered through the same generic section/item hierarchy |
| B: adaptable Career UI | Data loading, empty/error/loading, host route | New `ProfileHostAdapter`; no Workspace context or AppShell |
| C: product business components | Structured forms, imports, fact confirmation, archive/sync/edit/revision | Remain in original product; excluded |
| D: forbidden plugin dependencies | Repository/Dexie/IndexedDB, Next shell, Electron/Node, Agent runtime | Not imported or bundled |

The editable ProfileWorkspace is over 3000 lines with intertwined writes. A full extraction would exceed this PoC. Reusing the existing A presentation costs less and preserves its restrained information hierarchy without changing production architecture. This proves reuse of a display boundary, not migration of the original editable page. Semantic fact/status colors are not introduced or remapped; existing neutral exterior CSS uses Host foreground/background/border variables. No resume template or PDF styling is involved.

Data flow: `Hermes route → ProfileHostAdapter → ProfileReadClient.getProfile → FakeProfileReadClient → dedicated synthetic fixture → validated display snapshot → existing ProfileCareerView`.

- New code: `poc/profile-packaging/{plugin.tsx,ProfileHostAdapter.tsx,client.ts,fixture.ts}`. Type-only ProfileSnapshot reuse does not import the earlier canonical client implementation or production schema at runtime.
- Fixture explicitly marks every person/school/company/project/award/language/contact fictional; email uses example.invalid, phone is non-dialable text. All seven sections are deterministic, repeated reads return private copies. Existing demoCareerProfile is not used.
- DTO is display-only, **not Resume Schema v2 and not a formal Profile Domain API**. No Schema modifications.
- Client exposes one asynchronous read returning unknown at the boundary; parseProfile validates required display fields and rejects malformed responses. Null means empty. Loading/success/empty/service error/invalid response are distinct. No fallback turns an error into successful content.
- Refresh calls the same client and clears prior display while loading. Effect cleanup marks an abandoned request inactive; late results cannot update a disposed/replaced view. No network, backend, arbitrary URL, storage, repository or mutation capability exists.
