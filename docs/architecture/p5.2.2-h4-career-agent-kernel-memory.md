### Profile semantics decision

- routine preference memory = same Profile identity revision；`version` 是 CAS 修订号，成功且有变化时精确加一，`profileVersionNumber`、Person 和当前 Profile ID 不变。
- explicit Profile snapshot/version = new Profile identity；现有 `createProfileVersion()` 的显式版本语义不变。
- 偏好命令在既有 profiles/appMeta 事务中检查 current、Person、expected revision，写入同 ID Profile、active context 与 operation receipt；重复 operation 重放幂等，冲突拒绝，去重后无变化不增加 revision；事务失败回滚，提交后读回。ResumeBranch/Revision 不参与事务、不复制、不改归属。

### 候选、交互和召回

Hermes 只提供受当前消息原文、quote、hash 与 Host Person/Profile/revision 绑定的候选；临时意图不创建长期候选，混合或不明确意图要求澄清。修改只更改候选；拒绝清除候选并标记来源防止复活；明确保存才调用 Repository。Host 根据确认回执刷新当前 Session revision，保留选中的 Job、Resume 和 Revision；新 Session 从当前 Profile 获取受约束的偏好投影，不需要旧聊天。实际自然语言理解由 Hermes 模型执行，定向测试使用合成模型输出，不等于真实 Provider 资格验证。
