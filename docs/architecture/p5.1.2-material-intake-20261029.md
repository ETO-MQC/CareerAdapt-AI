## 1. 统一数据流与复用决策

```text
AI Workspace 的 + / 整个对话区域拖放       简历中心“导入资料”
                  \                     /
             AgentAttachmentStore + WorkspaceRepository
             会话所有权、原始字节、Hash、稳定 attachmentId
                              |
             MaterialIntakeService / material_intake Facade
                              |
             ResumeImportOrchestrator.extractSourceDocument
             原生解析 → 必要时 Local OCR → 已验证 Vision / 人工核对
                              |
             原有 ResumeSourceDocumentV2 + provisional 包装
                              |
             Hermes 读取来源、分类、选择一个职业工作流
                    /             |              \
             resume_import     job_intake     Profile 材料草稿
                    \             |              /
                现有 review / confirmation / version / Repository
```

审计结论：`ResumeSourceBlockV2` 已包含页码、坐标、阅读顺序、引擎、置信度和原文，`ResumeSourceDocumentV2` 已包含质量报告。本轮复用这套结构，没有复制 CareerSourceDocument，也没有迁移旧 `resume-import-v2` 数据。

新增 `career-material-intake-v1` 包装包含 sourceId、attachmentId、sessionId、原始 Hash、文件名、MIME、完整规范 SourceDocument、分类、核对状态、草稿引用和警告。它不是正式 Profile/Resume/Job。所有持久化继续经过 WorkspaceRepository 的现有 appMeta / 导入草稿存储。

原始字节在本机持久化，Map 只作缓存。刷新后的工具调用通过稳定 ID 恢复并复核 Hash；来源注册成功后不再依赖刷新前的 File。材料解析结果、原始字节 Hash 与规范文本 Hash 各司其职。Profile 材料以原文件 Hash + 规范文本 Hash 复用核对草稿；不同入口重复上传不新建第二份正式事实。已确认材料明确返回 already_saved；其余重复与冲突继续走既有 Repository 对账。

## 2. A：附件交互与生命周期

- 复用 AgentComposer；保留 +、选择简历、导入岗位、从资料库、工具。整个对话区域可以拖放，Composer 内拖放不重复登记。
- Chip 提供文件名、文档图标、图片缩略图、登记/失败状态、预览和移除。图片、本地 PDF 和文本可预览；DOCX 在来源核对中查看解析内容。
- 待发送附件按 Session 持久化，刷新后恢复。失败文字与附件恢复到提交时的 Session，并保留用户后来输入的内容。异步旧会话结果不会直接替换当前选择。
- 登记后提交的附件离开编辑区，允许继续编写下一 Turn。忙时发送复用现有 PendingUserInput，增加 Hermes 标记及附件引用；下一 Turn 仍由 Hermes 执行，未调用旧 Native 执行链。
- 队列的文字、附件与页面上下文写入现有 AgentMessage metadata，可恢复；跨 Session 不自动消费。Stop/Cancel 保留未提交附件与来源，确认方式选择取消时恢复文字和文件。
- 新增 agentSessionId 的 executor 透传，修复旧快捷导入在增强所有权校验后缺少 Session 身份的问题；没有放宽校验。

## 3. B/C：解析、OCR、Vision 与人工核对

原生 PDF 文本、DOCX、JSON、Markdown、TXT 继续使用已有解析器。非简历 JSON 复用现有 JSON 来源块适配器，不强制解释为简历。已有提取结果可交给 resume_import 继续映射，避免重新解析同一来源。

图片、扫描 PDF、损坏/不足的文本层进入已有 Local PaddleOCR Adapter。页码、bbox、阅读顺序、引擎版本和 extractionConfidence 保留；低置信度不自动成为确认事实。没有新增或替换 OCR 生产依赖，也没有宣称替代 OCR benchmark 已完成。

Local OCR 不可用时，只有 Provider 的模型元数据明确声明 image 输入，或相同配置已有成功图片请求，才使用现有 Vision 转写 API。能力查询不发送材料。未知、文本模型或失败回执会落到人工核对；原 attachmentId 保留，支持同任务补充转写。转写标记为 `manual_transcription`、extractionConfidence=0、待确认，而非伪装成 OCR 原文。

Vision 转写提示兼容证书、奖项、JD、成绩单与经历材料，并保留 untrusted-data 指令边界。当前图像转写复用 CareerAdapt 的既有 Vision Adapter；Hermes 接收带来源的规范文本，不新增 Hermes 文件输入协议。PDF/DOCX 没有作为 `file/input_file/file_id` 发送给 Hermes。

## 4. D：材料分类与 Hermes 工具

新增高层 `career.workflow.material_intake`，生产工具面变为 9 个 Facade + 4 个只读工具，精确目录测试同步。

第一次调用读取精确 attachmentId，返回规范来源。Hermes 根据来源作语义判断，再提交结构化分类；Host 只校验 Schema、blockId 和逐字 quote 是否存在，拒绝无来源的分类证据。

材料枚举为 resume、job_description、award、certificate、education_record、project_evidence、work_evidence、skill_evidence、portfolio、career_narrative、other、mixed。分类输出包含置信度、候选目的地、建议动作、来源证据和未决歧义。

用户明确目的优先；无明确目的时单一用途给出简洁建议，多用途只问一个高价值问题。这些规则写入 Hermes Run 指令与工具描述；Host 没有扩展名分类器或第二个语义 Planner。文件名和来源正文均作为不可信数据，附件元数据以精确 ID 进入锁定 Run 的 instructions/context。

## 5. E：三个目的地与事实边界

| 目的地 | 实现与确认边界 |
|---|---|
| Resume | 已有 resume_import → semantic mapper → review → confirmation → Repository，仍为 Resume Schema v2 |
| Job | job_intake 接受 attachmentId 和/或粘贴 JD，统一提取后复用原 requirements graph / dedup / version / confirmation；正式 RawInput 保留材料 sourceId、attachmentId、Session、Hash 与 block refs |
| Profile Material | provisional 源文档通过既有字段映射与导入草稿生成候选；候选包含 canonical field、值、原 quote、sourceBlockIds、confidence、verificationState；复用对账和人工确认，不建立第二套资料库 |

Profile 材料默认不创建简历。纯本地解析对非简历证据不会把“证书”等首行当作人物姓名；无法可靠映射的内容保留在未映射来源中，交给 AI 字段整理或人工核对。AI 推断不直接升级为确认事实，未确认内容不会进入正式 Profile、Resume、预览或 PDF。Fact Guard 阈值未改。

## 6. F：产品入口与实际 UI

简历中心原快速创建区域第 5 个位置改为“导入资料”，用于证书、奖项、成绩单和经历证明。它调用同一个 MaterialIntakeService，核对仍使用 ResumeImportWizard，默认不勾选“同时创建通用简历”。来源文件名与来源块数明确展示。

AI Workspace 没有增加永久工具栏按钮。来源解析进度复用 AgentImportProgressBus 与现有 Tool Activity/Timeline；进度增加 Session 身份，避免旧会话处理进度串到新会话。Profile 材料草稿正确投影为现有核对 artifact。

已通过实际 Edge/Playwright 页面验收：第 5 入口、Profile-only 默认值、整个对话区域拖放、文本预览、刷新恢复、移除、图片缩略图与 1024px 图片预览。没有执行全站视觉审计。浏览器插件无可用浏览器，使用项目 Playwright。截图位于 `.tmp/p512-ui-delivery-results/`，均为修改后截图。

## 8. 限制与后续授权

- 本机 Local OCR health 为 configured/modelAvailable/runtimeAvailable=false（未配置 PADDLEOCR_VL_ENDPOINT）。本轮验证 OCR 协议与固定样例路由，没有真实 OCR 准确率、速度或替代引擎 benchmark。
- Hermes 语义场景使用模拟 Provider；没有把用户原件发送到真实 Provider，也没有认证 12 类真实材料的分类/抽取质量。保留对真实复杂证书、成绩单、mixed 文档的质量验收限制。
- Vision 能力未知时采用保守人工核对；没有元数据、也没有成功图片记录的实际可用模型会先走这条恢复路径。
- 文件/页数限制沿用当前导入能力；未扩展超大文件或超长 PDF。附件备份导入、长期来源清理与完整真实文件矩阵未在本轮认证。
- 原始文件在本机来源存储保留；本轮不进行文件批量清理。没有新增表、依赖、事实阈值或隐式资料库写入。
- 验收后用户追加授权本轮源码提交并推送；提交与远程状态以 Git 和最新交接为准。未打包，已有 release 目录不包含本轮修改。完成 P5.1.2 后停止；P5.1.3 与 P5.1.8 均需后续授权。
