## 实际通信与所有权

Main是Native Lifecycle/Synthetic Grant Controller，不是生产Issuer。它拥有随机用户权限命名管道、每次启动的HMAC密钥、enabled/epoch/lease状态和D3 append+fsync文件ledger。Main不import Repository/Dexie。原生Python Plugin只import标准库和锁定tools.interrupt，不持有资料或第二套业务引擎。

Application Renderer在fake-indexeddb内存后端使用既有CareerAdaptDb schema和唯一注入WorkspaceRepository，固定workspace→Repository绑定；同ProfileQueryService/Adapter/Gateway执行。没有打开默认/真实数据库、增加业务数据库或新表。完整应用bundle确实含Dexie，按正确进程边界保留，没有扫描排除伪造隔离。

Main通过自身native connection读取精确Session REST记录，并核对启动时批准的合成workspace/cwd策略后才签发D3 grant。Session/Turn/ToolCall先作为关联，不作为单独授权凭证；Renderer没有Scope或Grant Setter，contextChanged只能失效旧grant。**该原生REST绑定的完整Host动态资格尚未取得。**

Preload固定attach/lifecycle/contextChanged/verify/started/complete/onRead，Main复验WebContents、mainFrame、启动origin、请求关联与结果scope。Domain超时15秒、pipe idle65秒、Session查询5秒；命名管道无TCP Career服务，readableAll/writableAll关闭，另加随机名称和每次运行HMAC。Windows默认DACL使用未进一步做SID级实测，不宣称抵抗本地恶意代码。

## 撤权与UNKNOWN

真实plugins-store的setPluginEnabled接线为Renderer→Preload→Main；Main先enabled=false、epoch++、清grant并fsync记录，再返回，之后才更新disabled inventory。失败卸载本地贡献并显示error，不显示撤权完成。Main重启/管道意外断开/Renderer退出或reload失效旧grant，不恢复授权。

交付采用READY引用→Python暂存CANDIDATE→commit-delivery重新校验→AUTHORIZED。单测证明撤权后的旧closure/在途/已排队candidate不能commit。最终commit为线性化点；已commit发布不能追溯撤回。**真实Native调度、最终ACK排队竞态仍须C6验收。** Stop只复用原生线程中断协作丢弃结果，不声称杀死底层Handler；本轮真实Stop未验。

独立D3 ledger记录operationId、Session/Turn/ToolCall、payload hash、实际query handler次数、结果hash引用/合成结果与状态。重启只读历史，不构造grant、不执行handler；无可靠终态的ACCEPTED/DISPATCHED/STARTED为UNKNOWN，重复operation只返回UNKNOWN，禁止重执行。没有修改生产写入或声称通用exactly-once。
