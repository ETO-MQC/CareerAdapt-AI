## D1：同一 Repository 的纯查询

`WorkspaceRepository.readInitializedProfile` 在只读事务中只按主键读取授权 Profile 和对应 Person appMeta。不调用身份迁移、不扫描其他 Profile、不自动规范化或修复历史记录。缺失返回 NOT_FOUND；所有权不符/归档回收拒绝；旧版、身份元数据缺失或当前 Person 索引不一致返回 INITIALIZATION_REQUIRED。原 getProfile、迁移和正式业务初始化流程保持原状；未改变迁移策略。

ProfileReadPort 只是同一个 Repository 的接口。workspaceId 必须由 composition root 绑定至注入的 Repository 实例；当前数据库没有 workspace 租户字段，这个接口不能自己认证 workspace。

ProfileQueryService 复用 CareerProfile v2 和 canonicalProfileLibraryItems，输出 `career-profile-read-v1` 工具投影，不是第二套权威 Profile。支持现有 ResumeSectionTypeV2 栏目，无 Schema 扩展；project、skills 完整定向验收，其他类型仅复用现有投影，未逐类型认证。

分页按结构化条目原顺序，Cursor 绑定 workspace/person/Profile、来源 version+updatedAt、排序去重后的 sectionTypes、关键词及 limit；跨范围拒绝，版本变化返回 STALE_CURSOR。Cursor 是严格 JSON 而非签名令牌，不提供权限。每页最多20条、每条正文4000 UTF-16 code units、32 factIds、32引用，最终 UTF-8 上限256KiB，超限明确失败。nextCursor/truncated、textTruncated/referencesTruncated 区分分页和内容缩减。超过60条项目及技能均可列举；单条长正文无续读接口，明确标记截断，不宣称完整正文。

来源仅投影同 Profile 的证据 ID、事实来源句柄、block/range、来源轮次及 provenance kind，不返回附件路径/字节/原始引用正文和联系方式基础字段。任意用户正文未进行通用 PII 清洗。确认状态依据现有 factIds 和 confirmedByUser：缺少事实是 unknown，未确认 AI 建议保留 unconfirmed/ai_proposal，不能成为已确认事实。引用过多或非法路径式句柄被省略时显式标记。
