## 1. Runtime 路径与 parity

`electron/main.js` 开发态使用 `.electron-build/hermes-runtime-v4`，打包态使用 `process.resourcesPath/hermes-runtime`，即分发目录的 `resources/hermes-runtime`。`electron/hermesCompanion.js` 允许显式 `hermesRuntimeRoot/HERMES_RUNTIME_ROOT`，以该 Bundle 的 Python、source、site-packages 和 Skills 启动。`HERMES_SKILLS_ROOT` 指向 Bundle 的 `skills/careeradapt`，`HERMES_BUNDLED_SKILLS` 指向 Bundle 的 `skills`；`HERMES_HOME` 是独立可变配置、会话和缓存目录，不是 Bundle 根目录。

## 3. 后台请求、循环与终态

RP-01 v4 请求序号 51、52、54～60、69 的最后 user prompt 均为 `Review the conversation above and update the skill library. Be ACTIVE...`，与锁定源码 `agent/background_review.py` 的 skill review prompt 匹配。此前报告称为“curator”的10次请求应细分为 **每轮 background_review fork**，不是已证实的周期 curator 调度。

- `agent/turn_finalizer.py`：成功前台响应后，工具迭代达到 `_skill_nudge_interval` 或 memory nudge 后触发；中断时不触发。
- `run_agent.py::_spawn_background_review`：daemon `bg-review` 线程；继承主 Provider/model/凭据和会话快照，独立推理请求。
- `agent/background_review.py`：只给 memory/skill 工具，最多16 iterations；要求阅读并维护 Skill，因此可以产生额外 skill_view/patch/create 尝试。限制的是写权限，不是零推理请求。其 thread 不是前台 Run 的独立可取消 Run ID，也没有 CareerAdapt 前台预算回执。
- 周期 `agent/curator.py` 另有 `.curator_state`、enabled/paused/interval/idle，默认首次延迟、consolidate另受配置控制；gateway 定时 tick 调用。不能将两套机制合并计数。

本轮 standalone 加载探针在独立 Home 使用官方配置 `skills.creation_nudge_interval:0`、`memory.nudge_interval:0`、`curator.enabled:false`，**不包含后台行为验收**。正式浏览器模拟集成不修改生产用户配置。生产用户能力未删除或永久关闭，未减少工具集合，未修改 Runtime 补丁。

重复读取的最小修复先处理目标缺参/根任务缺失，并将“同参数同错误无进展应停止并指出缺项”传入 Run。脚本化 Provider 能验证工具协议和流程，但不能证明真实模型不会循环；自然模型重复读取恢复仍 UNKNOWN。已有终态归属测试覆盖旧 Run 回包不能覆盖新 Run。HTTP429/超时/参数错误使用本地注入，不冒充真实 Provider 认证。
