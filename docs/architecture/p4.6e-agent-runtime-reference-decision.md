# P4.6e Agent Runtime Reference Decision

本轮先完成外部参考与当前 bundled Hermes runtime 的能力核对，再据此限定实现边界。当前 bundled runtime 为 Hermes Agent 0.19.0（commit `eb52760564dbba2e5971fa54bd67384e281cd3b8`）；`source/hermes_cli/web_server.py` 实际包含 `GET /api/model/info` 与 `POST /api/model/set`，`ModelAssignment` 支持 `scope`、`provider`、`model`、`base_url`、`api_key`。`/api/model/set` 的源码说明该写入“仅对新 session 生效”，当前 bundled Web server 中没有被证明的 `session/set_model` 或 `set_session_model` HTTP endpoint；Hermes 的 `/model` 是运行中 CLI session 的独立命令。因此本轮可以采用原生模型配置边界，但不能宣称已有 Web 级 live session hot-switch。

Bundled resolver 还会把裸 `custom` assignment 解析为已配置的命名 custom provider；CareerAdapt managed entry 的 canonical ID 是 `custom:careeradapt`。Supervisor 只在 readback 对账时接受这一明确的 `custom` → `custom:*` resolver 结果，产品 fingerprint/status 仍保持稳定的 generic custom identity。

| Reference pattern | CareerAdapt current behavior | ADOPT / REJECT | Reason |
| --- | --- | --- | --- |
| [Hermes Web model API](https://github.com/NousResearch/hermes-agent/blob/main/hermes_cli/web_server.py)：`/api/model/info` 读取有效模型信息，`/api/model/set` 接收 provider、model、base URL、API key 并写入配置；官方实现明确说明写入对新 session 生效。 | Settings 通过 CareerAdapt 的 `update_config` 控制面修改配置，Supervisor 将配置变化作为 runtime replacement/restart 流程处理；浏览器不直接请求 Hermes model endpoint。 | **ADOPT** 原生配置边界；**REJECT** 把它解释成 live session switch。 | 由 server/Supervisor 内部调用原生 endpoint，保留浏览器只访问 CareerAdapt API；保存后新 Hermes session 使用新配置，当前语义 run 不被静默改写。 |
| [Hermes provider normalization](https://github.com/NousResearch/hermes-agent/blob/main/hermes_cli/models.py)：provider 通过 canonical alias 归一化，缺省值与 `auto` 有明确语义，OpenAI API 与 OpenRouter 是不同 provider identity。 | `normalizeAiProviderIdentity` 会把非 URL provider 原样小写，并在 URL 场景下用 host 推断 `openrouter` 或 `openai-compatible`；UI 当前没有要求用户填写 provider。 | **ADOPT** Hermes canonical provider IDs；**REJECT** 从展示名、URL 或模型名片段推断 provider。 | 内部保存 `openrouter`、`openai-api`/`custom` 等 Hermes 可识别 ID；普通 OpenAI-compatible 用户流程继续只填写 URL、key、model，provider 只作为内部映射或高级诊断字段。 |
| [OpenHands ACP provider registry](https://github.com/OpenHands/software-agent-sdk/blob/main/openhands-sdk/openhands/sdk/settings/acp_providers.py)：分别声明 initial model capability 与 runtime model switch capability；live switch 只有 provider/session 明确 advertise 才可使用。 | CareerAdapt 目前把模型配置 apply 与 Hermes process replacement/restart 绑定，尚无独立的 session-level capability gate。 | **ADOPT** “能力声明后才切换”的判定方式；当前 Hermes **REJECT** 未证明的 live switch。 | Hermes bundled Web API 只证明 new-session config write；因此 apply 不重启进程，释放旧语义 session binding，后续新 session 读取新配置。 |
| [OpenAI Codex config layering](https://github.com/openai/codex/tree/main/codex-rs/config)：effective config、来源、层级版本和受控写入分离，写入后以有效配置/readback 为准。 | P4.6d 已有 active/desired、fingerprint、generation、apply receipt 与 readback 投影，但部分状态仍围绕 restart/replacement 命名。 | **ADOPT** 单一 verified Supervisor snapshot、单 flight mutation、readback 后 commit；**REJECT** 搬运完整 Codex layer/managed-config 模型。 | CareerAdapt 只需要模型配置的有效投影与来源诊断，不需要新增持久化层或新的 Dexie 表；verified snapshot 仍由 Supervisor 投影到 RuntimeStatusStore。 |
| [Jan provider configuration](https://jan.ai/docs/agents/providers)：provider ID、API key、base URL、model 是最小配置；兼容端点先用 `GET /models`，`/model` 可在当前 agent 中切换；密钥编辑支持保留/清除语义。 | Settings 暴露 URL、API key、model，候选测试走独立 AI test route；连接测试和保存应用的体验仍混有 runtime 反馈。 | **ADOPT** `/models` 优先的轻量 connection test、candidate-only state、明确的 key retain/replace/clear；**REJECT** 把候选测试接入 active runtime。 | 连接测试只验证 reachability、auth、model presence；只有 `/models` 不足时才做最小 completion，不运行 tools/run/reasoning，也不写 active snapshot。 |
| [Open WebUI OpenAI-compatible connections](https://docs.openwebui.com/getting-started/quick-start/connect-a-provider/)：用户主要提供 URL 与 API key，模型由连接发现；多种 provider/protocol 在连接层处理。 | CareerAdapt 正常 AI settings 已隐藏 provider，但内部展示和 runtime 诊断仍暴露较多 provider、fingerprint、generation、URL 与内部代码。 | **ADOPT** URL、key、model 的低认知负担表单与单一 inline result；**REJECT** 把内部 runtime metadata 放在普通设置/Agent 页面。 | Provider identity 留在 server/Supervisor 与 Developer diagnostics；普通页面只展示当前模型、Ready、测试连接、保存并应用。 |
| [Continue ConfigHandler](https://github.com/continuedev/continue/blob/main/core/config/ConfigHandler.ts)：一个配置 handler 负责 cascade/reload，并通过 listener 发布更新。 | P4.6d 已移除 `AiRuntimeConfigCoordinator`，但仍需核查 `subscribeHermesStatus`、`refreshHermesHealth` 和 provider/runtime writers 是否重复写 RuntimeStatusStore。 | **ADOPT** 一个 Supervisor Active Snapshot → RuntimeStatusStore 的语义写入路径；**REJECT** 恢复 coordinator 或并行 active writers。 | health、turn、MCP 与 candidate 结果只能提供各自诊断/局部状态，不能覆盖已验证的 Supervisor active model/config。 |
| [LibreChat configuration](https://www.librechat.ai/docs/configuration)：文件配置变化通常需要重启才能被进程重新加载。 | 当前 CareerAdapt 把配置变化纳入 process replacement/restart，导致模型切换与进程生命周期耦合。 | **REJECT** 作为首选语义；仅在原生能力不存在且兼容性验证通过时考虑一个明确 fallback。 | bundled Hermes 已有 `/api/model/set`，可以保持进程存活并让新 session 使用新配置；本轮不同时实现多个 fallback。 |
