## Transport choice

Choose private inherited stdio for this bounded PoC. Backend owns one fixed `fake_service.py` child, no user-supplied command/path, no discovery socket, no HTTP listener for the Domain leg. Frames use 4-byte big-endian length, UTF-8 JSON, maximum 1 MiB; stdout is protocol only. Broker serializes exchanges and checks requestId. Service epoch changes per process, no automatic reconnect/retry. IPC failure surfaces as 502/503; a five-second read deadline kills a stuck fixture child, never fabricates an empty successful result. Explicit close drains by stdin EOF and waits at most five seconds, then reports failure if forced termination is needed. Read-only fixture has no operation outcome uncertainty from writes.

Windows ACL named pipes are an alternative for a separately launched long-lived owner and independent reconnect. They require explicit security descriptors, peer/launch identity and endpoint ownership; default ACL is insufficient. [Microsoft's named pipe security documentation](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights) describes those controls. No named-pipe implementation or ACL runtime qualification was performed. Stdio is demonstrably simpler here using already available libraries, but couples the fixture service lifetime to its broker; it does not establish a production supervisor or independently managed data owner.

The Renderer→Host→Hermes Backend leg uses the existing authenticated loopback Hermes API. This is the requested SDK path, not a newly exposed localhost Career Domain server. Private communication is on the Backend→Fake Service leg. OS-user isolation, native process ACLs and supply-chain trust still require future qualification.

## Limits and stopping decision

The required statement “disabled Plugin cannot use its original connection” is disproved for Renderer disable. Backend disable gates requests, but neither unloads broker nor changes its epoch. A cooperative cleanup request from Renderer cannot prove revocation against malicious same-realm code. No additional wrapper, token or silent lease polling is added to disguise that gap. Generic Python plugins execute in-process and are trusted code, not mutually isolated authorities.

Startup READY here is broker process-launch readiness; first hello establishes actual protocol readiness. Production readiness handshake, crash-before-hello, Host abrupt-kill/orphan reaping, automatic backend shutdown hook, already-running request revocation during disable and cross-platform IPC are **NOT QUALIFIED**. Host restart was tested with explicit broker close before shutdown; it does not prove orphan-free crash cleanup. These are reasons to retain PARTIAL, not claims of completed lifecycle qualification.

No Core change was attempted. Stop transport remediation at this gate; no full Domain Service or B2-B2. See [trusted confirmation audit](p5.2.0b2b1-trusted-confirmation-audit.md), [runtime decision](p5.2.0b2b1-runtime-release-decision.md), and [machine evidence](p5.2.0b2b1-evidence.json).
