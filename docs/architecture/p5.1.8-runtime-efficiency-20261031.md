## Production timeout与wire

现有request timeout默认1800s，但nonstream默认90s/Qwen floor180s；stream stale默认180s，socket read默认120s且在该锁定版本会提升至已算出的reasoning stale floor。对约300秒才响应的当前AMD/Qwen仍可能过早终止。

直接源码与实际AIAgent捕获确认：production默认 **streaming**；actualProviderId=custom（named custom:careeradapt被上游canonicalize）。直接写providers.custom:careeradapt配置而不处理alias将无法让get_provider_*读取它。最小兼容patch仅在canonical custom、AMD精确host及Qwen3.8-27B模型时映射回named key，复用既有providers.<id>.models.<model>.timeout_seconds/stale_timeout_seconds机制。

managed YAML按AMD host安装Qwen的request=480s、stale=480s默认，语义merge保留用户已有显式配置、其他模型和未知字段。没有全局HERMES_STREAM_READ_TIMEOUT/STALE_TIMEOUT生产覆盖；DeepSeek和其他host/model默认保持。stream socket read从已有model request policy获得480s，不需要另建transport。reasoning_effort=low wire保留；实际Agent原生产max_tokens=65536，未机械改为probe16384。

| timeout层 | 本轮结论 |
| --- | --- |
| Provider request | 1800s default → 480s AMD/Qwen model override; others unchanged |
| Nonstream stale | 90s implicit / Qwen reasoning floor180s → 480s AMD/Qwen explicit model override |
| Stream stale | 180s default/known Qwen floor; optional context scaling → 480s model config, existing floors/scaling preserved |
| Stream socket read | 120s default, raised to stale floor when applicable → 480s via the existing provider request timeout knob, not global env |
| Agent inactivity | GatewayRunner messaging path default1800s inactivity; 0 unlimited → unchanged; official v1/runs API path directly runs agent and has no shorter whole-run wall deadline |
| CareerAdapt run_start/status/stop HTTP | 30s control/request budget → unchanged; finite operations only, not the Provider generation duration |
| Host/SSE/browser stream | No local absolute or inactivity watchdog; SSE keepalive every30s → unchanged; comments map to progress and active lease remains single-flight |
| Runtime run deadline/UI polling | Run remains running until completion/cancellation/failure; UI shows processing and stop control → no UI redesign or production code change; full180s refresh/cancel browser regression remains unverified |

官方/v1/runs API直接执行Agent，不经过messaging GatewayRunner的1800秒inactivity wrapper；没有发现更短Run wall deadline。CareerAdapt run_start/status/stop的30秒仅是有限HTTP控制请求；run_events的requestSignal为undefined，无本地absolute截止。Hermes SSE每30秒keepalive，Bridge映射progress，Lease单消费者和停止reason保持。服务端/浏览器全链180秒验收限制见下。

### Root cause and final implementation

The Host recovery path could remain blocked on SSE after refresh; authoritative status was read only after stream termination/failure. Terminal SSE delivery was consequently a correctness dependency. Independently, user Stop interrupted execution and recorded cancellation metadata but did not persist an absorbing cancelled run handle before waiting for remote stop.

`HttpHermesBridgeTransport.runEvents` now checks the original run's authoritative status before opening SSE and every 2 seconds while an SSE read is pending. Completion/failure/cancellation maps into the existing runtime event projection and Repository/CAS path; it never submits a prompt, starts a Run, executes a Career tool or writes business facts. Status unavailability emits a diagnostic progress event and preserves nonterminal state. Local SSE cancellation after status reconciliation affects transport only. No second Run store or Agent loop was introduced.

The Host fences late events for a terminal run's original turn and establishes cancelled state before remote stop. Repository saveAgentSession enforces absorbing same-run terminal ownership inside its existing Dexie transaction, rejecting conflicting terminal/nonterminal snapshots before appending their messages, even at a higher revision. A new legitimate turn/Run remains allowed.

Consumer replacement was not needed for correctness and its prepare hook was removed. Candidate source/test snapshots are archived under `.tmp/p518b-r2-retired-*`; installed runtime was re-prepared without the candidate, preserving the accepted AMD/reasoning/timeout/context patches.
