# P5.2.1 — Visual Direction

2026-11-03。三套方向共享 CareerAdapt 绿灰品牌、现有字体和32/36/40px控件，不是三个新品牌。以下比较是设计推演；实际可运行原型只实现推荐C，未虚构A/B截图。

| 维度 | A 原有风格强化 | B 原有风格 + LibreChat/Open WebUI交互 | C 原有风格 + assistant-ui组合思想 + Lujie规范治理 |
| --- | --- | --- | --- |
| 视觉 | 最接近现有紧凑管理工作区，绿灰/弱边框 | 同一品牌，消息更自由，导航与设置分组更丰富 | 同一品牌，正文平面化，工具/产物清晰分层，规格统一 |
| 布局 | 现有业务布局为中心，聊天作为一页 | 会话/项目为主，chat + docked artifact | Host壳保持权威，纯展示消息/工具/composer + 并排工作区；业务页独立架构 |
| 组件 | 直接复用 Product 薄包装 | 复用Product，增加会话与附件/工具/产物组合 | 同左，集中size/variant/state/padding契约，消息部分与Runtime分离 |
| 优势 | 风险小、品牌连续、近期可落地 | 对话效率与上下文反馈强，来源/产物更可达 | 可从Profile逐步落地，边界清晰，长期减少页面样式漂移 |
| 缺点 | 仅规范化现有页面可能解决不了Host聊天体验断层 | 容易把通用聊天平台复杂控制搬进职业产品，Host chrome改动风险大 | 初期需状态/行为契约与组件验收，不能只写一层CSS |
| 实施成本（相对） | 小；以业务展示层局部调整为主 | 中高；导航、chat、settings、pane贯通 | 中；先语义适配与Profile，再评估Host可扩展pane，不一次迁移所有页面 |
| Hermes兼容 | Career局部适配高；全局外观仍需Host配合 | 局部高、整体shell改造需独立可行性gate | 最清楚：公开SDK+CSS消费，缺Host API明确阻塞，保留已用assistant-ui Runtime |
| 长期维护 | 低至中，但页面差异仍易累积 | 高，若照搬状态库/多Provider控件将跟随两套平台演化 | 低至中，组件契约和Host版本快照需持续维护 |
| 建议 | 可作最小退路 | 吸收交互，避免平台级移植 | **推荐供用户验收，尚未批准生产实施** |

推荐C，同时吸收B的导航分组、输入法保护、工具摘要与产物版本/来源；A提供品牌与尺寸基准。没有采用Appearance Hub主题、透明玻璃、纸纹、外部字体包或参考项目的源码。

## 页面设计

顶部：56px平静页头，当前位置与当前任务分层；全局状态轻量但可进入详情；设置入口明确。模型控制集中在输入区，不在多个位置重复完整选择器。原生标题栏由Host负责。

左栏：业务入口、最近会话、项目、设置/用户分组；图标18px，行38px，文字12–14px；选中用浅accent底与字重。1024采用64px rail，1440起默认216px。原型未列全Host入口不是批准删除：正式仍保留Capabilities/Messaging/Artifacts/Agents/Cron/Webhooks/布局/权限等功能，可在低频区或Host导航访问，逐项盘点后验收。

聊天：用户浅底气泡，AI正文不套大卡；阅读列最大720px；工具摘要是一行可展开活动，不把参数JSON作为默认正文。错误紧邻失败动作、保留输入；消息操作位于末尾，键盘可达。Markdown/代码块规范为12px边距、单独横向滚动、复制按钮与语言标签；原型未引入解析器与代码高亮。

输入器：同一个框容纳文本、附件、模型/工具摘要和发送/停止；文本自适应48–160px，长内容内部滚动。原型Enter发送、Shift+Enter换行、IME不发送；不会执行真实请求。工具更多与权限归Host，不能在原型伪装真实授权。

右产物：**Conversation Pane | 9px Resizable Divider | Artifact Pane**。默认40%，34–50%可拖/键盘；独立滚动与错误边界；任务id/产物id来源示意，建议/来源切换；关闭保留对话与比例，页头显式恢复。1024仍并排，默认chat约555px/产物376px。正式拖动还须满足min420/min320的双向约束。不得用覆盖聊天的sheet作桌面默认。

Profile：人物/版本摘要 + 分类/条目/详情，复用原合成Profile展示，不搬真实ProfileWorkspace。Jobs保留列表/岗位证据，Applications保留阶段与记录，Studio保留结构化编辑与独立白纸A4。统一控件，不统一成同一张页面。

## 用户验收重点与当前限制

确认品牌连续性、双栏比例、信息密度、1024可读性、Profile分类/详情关系、浅深主题，以及原型里9–10px次要说明是否需要更大（生产规范建议≥11px）。候选标题21px与原页标题18px需在后续确定，不默默改全局值。

原型是视觉交互示例，Jobs/Applications/Studio为明确标示的占位信息架构，不提供实际功能；Profile搜索输入未接正式搜索；模型选择/附件只在内存展示；无真实流式Markdown/文件预览/Domain写入。生产Host可扩展pane接入仍待gate。完成本轮后等待用户验收，未经确认不进入P5.2.2。
