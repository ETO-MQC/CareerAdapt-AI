# P4.7b Future Capability Note — Calendar (Document Only)

This note records a future extension pattern. P4.7b does not implement
Calendar, add a Calendar schema, add a Dexie table, select a UI component, or
change Hermes runtime behavior.

## Intended boundary

When the capability is eventually approved, the shape should remain:

`Calendar UI → Calendar Domain → Calendar MCP → Hermes native MCP discovery/tool selection`

The Calendar Domain would own local structured events and deadlines. Calendar
MCP would expose narrow `search/get/create/update/delete` operations. The UI
would use a mature open-source calendar component selected in the future; no
component decision is part of this phase.

Possible event types include:

- `exam_registration_deadline`
- `exam_date`
- `job_application_deadline`
- `interview`
- `career_event`
- `personal_reminder`

The same current architecture should later be able to add Calendar, Web,
Email MCP, Job Search, Job Application, and Browser automation without
changing `HermesCareerAgentRuntime`. Each extension should arrive through its
own domain/MCP contract and existing Host/Repository/confirmation boundaries.

## Permission principle

Read/search operations may be performed automatically when they are required
to answer the user's request. `create`, `update`, and `delete` must initially
require explicit user confirmation. There must be no silent deadline insertion.

For an external fact discovered on the Web, the safe sequence is:

`Web evidence → proposed Calendar event → user confirmation → Calendar write`

The proposal should retain the source evidence and clearly identify uncertain
date/time or timezone fields. A Web result is not itself permission to write a
local event.

## Future design questions

Before implementation, decide the event identity/idempotency contract,
timezone and all-day semantics, source-evidence retention, recurrence policy,
conflict handling, deletion confirmation language, and how Calendar MCP
authorization maps to the existing WorkspaceRepository boundary. Those are
future design tasks, not hidden P4.7b implementation requirements.
