## 权威来源与语义

- `hermes_state.py` 的 SessionDB / `HERMES_HOME/state.db` 是正式历史来源，Gateway 管理创建、恢复、历史读取。Session runtime ID 为短 UUID；stored ID 为时间与随机后缀。两个样例 ID 不同不代表数学上的无限唯一性保证。
- 空白新会话是原生 draft，首次 prompt 才懒创建 DB 行与历史列表条目；不将空草稿未进入列表当作丢失。
- 原生会话消息读取按自增 `messages.id` 排序，保留插入顺序，避免非单调墙钟时间破坏 tool/result 邻接。合成历史中用户/Assistant 正文与时间字段实际恢复。
- Renderer session cache、`$sessionStates` 和 Gateway 运行态均是投影，不是磁盘历史数据库。完整关闭/重启后重新 resume，runtime ID 可以变化，stored ID 保持。
- 文本草稿使用原生 `hermes:composer-drafts:v3` localStorage，最多保留 50 条非空文本；受 localStorage 可用性/容量限制。
- 附件草稿仅内存保存：同一 Renderer A/B 切换可恢复，reload/重启后附件芯片消失。没有伪装为已恢复，也没有新建附件数据库。
- 已提交 TXT 的持久引用在原生用户正文 `@file:` 中；乐观 Renderer `attachmentRefs` 数组不持久，不用该数组为空否定正文引用。真实已暂存文件与原文 SHA 相同；移动单个合成原文件期间，暂存副本仍可读，随后原文件已复位。
- 原生 journal 是恢复辅助：24 条、7 天、流式写入节流 400ms；不保证超出保留边界后的 UNKNOWN 提示，不是服务端幂等键或任务自动续跑协议。
- 原生列表/恢复/历史接口已审计，删除接口存在但未调用；归档/重命名未做破坏性或无关验收。

## 最小修复

`p522-host-a02-04-patches.mjs` 通过现有 Renderer opt-in 集成，要求同时启用 `--careeradapt --reliability --attachments --session-persistence`；外部 Hermes 文件未写入。

1. 原生 journal 会清除已空闲的请求，即使本地 error 为 UNKNOWN。补丁立即将 UNKNOWN 尾部写入同一 journal，并让恢复前的空闲投影不能清除已有 UNKNOWN。权威历史确认已完成时仍使用原生 caught-up 合并清除过期日志。

两处均有锁定 SHA/唯一锚点，未改 Main、Preload、Python、锁定 HEAD、Schema v2、Repository、Fact Guard、生产依赖或 Career 数据。默认 optIn=false 未加载项目补丁；本轮未打包或更新 release。
