## 3. 各 Skill 职责、契约、策略与差距

### candidate-profile-interview

- 触发：从零建立/补全 Profile，或回答活动 Intake 问题；不接纯故事、Fit、简历生成/定向优化。
- 输入：person/profile/session、Profile revision、活动 question/revision、已确认事实与原话、answered/skipped ledger、最新用户 turn。
- 输出：kind、问题标识、confidence/reason、单资产 patch 或 skip、未解决维度和一个 next-turn plan；不是未经确认的简历正文。
- 流程/提示策略：先解析当前问题，再分 answer/correction/skip/reference/control/new asset；自然一轮可提多资产，定向 follow-up 只改绑定资产；每次一题，每个主要资产最多两次高价值追问，允许零题；最终回显事实再确认。
- 依赖：profile_intake_turn/finalize facade、现有 Intake source-turn、成熟度与确认链；related_skills 为 story-mining/review，属于语义关联而非强制串行调用。
- 已有：多资产采集、跳过 ledger、原话与 turn、成熟度、Profile commit review。
- 缺失/未证实：多轮自然模型是否选择最有价值问题、长对话是否去重；30案例只有1个直接覆盖该 Skill，不能推断完整访谈质量。
- 冗余/冲突：FACT SAFETY、STOP/RECOVERY 与共享 v2 多处重述；旧 STOP“answer supports multiple assets 就停止”与新“自然 turn 多资产”需明确前者仅针对定向 follow-up 歧义；全局 resume_only 默认与明确 Profile intake 目的地需说清，不能让默认句替代明确入库授权。

### career-story-mining

- 触发：提炼单段经历的行动/方法/挑战/结果，不承担 Profile 完善、Fit 或简历落库。
- 输入：准确叙事与 source turn/附件、已有资产、可选且标明岗位专用的上下文、固定人物/版本/session。
- 输出：目标资产 ID、source-bound candidate patches、证据链接、confidence、缺口与一个建议问题。
- 流程/提示策略：先保留事实，再分解释；只在身份清楚时拆资产；Context→Task→Action→Method→Challenge→Result→Ownership 为内部透镜；困难时给3–5个例子，只有用户选择/回答才产生事实。
- 依赖：必要时 context.retrieve；向 intake/tailoring 交接提案，本 Skill 无正式写工具。
- 已有：个人/团队边界、定性结果可用、不强求数字、不强塞 STAR 表、一次一题。
- 缺失/未证实：没有专属可写故事库，也不应新建；真实模型能否随答案自适应、从提示例子中保持事实隔离尚未认证。
- 冗余/冲突：前三节泛化候选 patch 与后文三四条复用 bullets 有重复；“source provenance 缺失就停止”不应误读为要求外部证明，当前用户 turn 本身可作来源。

### job-fit-analysis

- 触发：人与指定 Job/JD 的匹配比较，不生成或修改 Resume；Tailoring 不必先单独调用它。
- 输入：版本绑定 Job/requirement IDs、已确认 Profile/资产、可选 Resume revision、session。
- 输出：requirement→evidence matrix、五组 fit summary、缺口、问题、confidence、tailoring priorities，保留 analysisId 与版本。
- 流程/提示策略：复用 JobRequirementGraph；保留 must/preferred 和条件关系；direct/transferable/partial/unknown/conflicting/mismatch 区分；默认零题最多一题；unknown 不解释为不会。
- 依赖：job_fit facade、careerIntelligence matrix/图与保存的 Job 版本；related tailoring/review 不等于必须先后运行。
- 已有：图复用、版本矩阵、成熟度、可迁移证据、五组摘要政策。
- 缺失/未证实：结构化证据匹配不等于开放语义理解；澄清价值 high/medium/low 主要是提示政策，Host 不是经过校准的信息增益优化器。
- 冗余/冲突：INPUT“confirmed profile facts”易弱化当前会话证据，但 v2 已承认用户自述；fit facade 实际读面与未绑定会话声明必须区分，不能仅靠提示词声明就说任意新 claim 已用于 Fit。

### resume-tailoring

- 触发：用户指定 Job/JD 改岗位简历；不接通用生成或纯 Fit。
- 输入：Job/JD、来源 Resume/Profile revision、graph/blueprint、原话和偏好、固定人物/session。
- 输出：五态 gap scorecard、requirement/evidence map、可逆字段 diff、claim/provenance/maturity、review 与确认清单，区分 proposal/apply。
- 流程/提示策略：先分析；选经历→排序→有证据的岗位语言→已确认新回答→ATS词→删低价值内容；steady 不追问，competitive/max_fit 有界；要求 requirement→answer/sourceTurn→claim→diff。
- 依赖：tailor_resume facade、tailoringService/claimPolicy、现有 clarification answer receipt、review、用户确认与Repository/CAS。
- 已有：resume_only 分支隔离、用户新技能、否认/跳过、条件组、固定问题预算、来源版本与拒绝旧提案。
- 缺失/未证实：自然语义迁移/追问收益未盲评；当前问题队列生成后冻结，回答推进 ledger，不等于每轮重新挖掘全局最高价值问题。
- 冗余/冲突：Skill competitive 上限2，Host 默认/通常上限1；Skill 已明确服从更小冻结预算，因此不是执行门禁漏洞，但措辞可统一。旧“never invent skills”应理解为禁止无依据新增，不是禁止用户确认的新能力。

### resume-review

- 触发：无目标岗位的现有通用简历检查/改进；目标简历评审留在tailoring facade。
- 输入：选定 branch/revision、正文/呈现层、来源证据、固定绑定。
- 输出：四视角 findings（severity/location/evidence/recommendation/confirmation）、字段 diff、ATS eligibility/final presence、页数/压缩观察、release checklist。
- 流程/提示策略：来源与确认→ownership/内容→一次安全ATS补词→重新Guard/review→实际预览/PDF核验。检查通常零题。
- 依赖：必要 resume.list；compose_resume general/update_existing 产生review提案，review-only 停在提案；批准改进才可继续。实际 Reviewer 是领域确定性函数，不是独立自然模型 reviewer agent。
- 已有：去重、套话、低密度、职责/指标来源检查、review diff ledger、四诊断面、支持词安全修复。
- 缺失/未证实：最强经历排序/真实首屏/语义相关性未校准；Skill 要求完整视觉检查不意味着每次运行已经取得截图或真实PDF抽取。
- 冗余/冲突：INPUT“Profile evidence for every material claim”与 v2“user-confirmed counts”措辞不一致；实际 Writer/diagnostics 已有 sourceTurn例外，需保留。无源简历ID的纯文本审阅是对话建议，不能伪称已执行正式compose工具。

### resume-composition

- 触发：无 Job 的通用简历创建/更新。
- 输入：profileId/expectedRevision、general、可选sourceResumeId、偏好/证据和review context；最新用户原话由Host注入，模型不提交sessionSource。
- 输出：graph/blueprint/writer/reviewer不可变checkpoint提案，确认后才返回branch/revision；ResumeDocument仍只派生。
- 流程/提示策略：确定性建图/blueprint→Writer（AI或有标记fallback）→claim/Guard→review/有界修复→固化checkpoint→确认精确提交，不二次写作。
- 依赖：compose_resume facade、sessionConfirmedSkills、EvidenceGraph/Blueprint/Writer/Reviewer、service与现有Repository确认/CAS。
- 已有：已确认 familiar/learning 限定表达、会话明确技能 overlay、新建和选定通用简历更新、Revision/PDF、Profile/其他分支隔离。
- 缺失/未证实：任意开放叙事不是自动事实通道；overlay依赖技术词表与正则，仅处理明确技能。新学历/公司/日期/指标/ownership 应继续走既有事实审核，不应扩展overlay。
- 冗余/冲突：purpose及INPUT强调Profile，但末段允许current user；是契约描述不完整，并非实现仍无会话消费。FACT/STOP重复，三四条fact bullet与2–4条项目bullet应区分事实复用与最终呈现。

## 5. Claim Safety V1 → V2：实际差异矩阵

V1为冻结1.0.0 Skill与旧来源中心语义；V2为当前2.0.0政策及已有Host实现，不是本轮开发。

| 项目 | V1倾向/限制 | 当前V2实际状态与边界 |
| --- | --- | --- |
| Profile缺项 | 易当作不能写/无依据 | Skill明确unknown；技能可用当前明确自述，不能推断不会 |
| 用户新技能 | 依赖Profile fact路径 | facade从持久化当前UserMessage建立CompositionSourceTurn，service加入overlay；tailoring有answer receipt→claim链 |
| user-confirmed capability | 容易强求项目证明 | 已支持confirmed_capability/familiar/learning；基础接触/正在学习保持限定 |
| source/confirmation | Profile provenance为主 | graph sourceTurnIds/excerpts/confirmed，claim保留turn，checkpoint和Revision保留来源；语义自述confirmed不等于已批准正式写入 |
| 同步范围 | 混淆简历与Profile | resume_only默认；resume_and_profile仍须独立Profile审核确认；无隐式反向同步 |
| 可迁移 | 字面词缺失易低估 | Skill允许支持的同义表达；R/Excel不证明Python，自动语义质量仍未认证 |
| 高风险客观事实 | 严格Guard | 原规则/阈值保持；新数字/实体/职责升级拦截，缺来源不可补造；新outcome原规则medium仍needs_edit，tailoring policy将hard-fact findings阻止 |
| Writer | 只以Profile fact确认 | claimFor现有明确session skill例外，必须匹配skill label、confirm/sourceTurn/excerpt，其他claim仍需sourceFacts |
| Reviewer | 文字要求逐条Profile | diagnostics接受factIds或sourceTurnIds，风险独立；旧INPUT文案仍不够准确 |

Guard源码：`src/domain/adaptation/factGuard.ts`。检测新增数字（含单位/中文数）、学校/公司/组织/角色、固定词表工具/技能、成果词和四类职责/熟练度升级。证据比较为归一化字符串包含；未允许high→blocked_high_risk，未允许非high→needs_edit；AI合并不能清除规则高风险，AI失败保留规则。它不是开放世界事实核验器。

实际缺陷/风险分级：

- **已观察的文案矛盾**：Reviewer旧Profile-only INPUT、Intake多资产stop条件、composition旧Profile中心描述；不能据此声称当前消费链不存在。
- **源码可见限制**：有限工具词表、中文规则与substring匹配可能漏英文ownership/无单位数/否定上下文；session overlay仅词表+正则，分句可能限制自然自述与成熟度理解。属于覆盖风险，未在本轮新建攻击测试证明每种可突破正式写链。
- **不能从模型标签推断已保护**：source_confirmed等是分析标签，持久化仍用原schema。每条claim需看实际source turn/绑定/确认，不可因模型写了user_confirmed就放行。
- **现有硬边界保留**：未降低Guard、未改Schema/Repository/CAS/Revision；不支持的高风险客观事实应hold out或经既有入库审核，不能把能力确认政策推广到公司/数字/ownership。

## 7. Writer / Reviewer / ATS 四维现状

Writer：`ResumeBlueprint.ts`选择/排序资产，`CareerResumeWritingService.ts`调用structured AI并sanitize；失败显式记录deterministic_fallback，`ResumeWriter.ts`按sourceAssetId/typed字段组织summary/skills/project bullets，2–4条为目标、最多4条，不够证据可以更少；claimFor运行Guard后筛选。岗位关键词来自版本矩阵/blueprint，不是无条件注入JD词。

Reviewer：`ResumeReviewer.ts` 是确定性全局pass，去重、filler/口语、信息密度、段落、来源指标、ownership，保留remove/rewrite/verify/shorten/deduplicate ledger；允许一次有界repair，再复核。ATS repair只对已支持且source excerpt有精确词的项目工具字段加入，最多4词/项目；不是任意语义重写器。

| 维度 | 当前实际计算 | 尚不能证明 |
| --- | --- | --- |
| HR Scan | qualityDiagnostics的定位覆盖、filler/paragraph观察；strongestExperience=unknown | 真正招聘者首屏判断、最强经历语义排序、录用效果 |
| Content Quality | 规则信息密度/去重/ownership检查、AI Writer与规则review | 人类可读性/相关性的校准权重；缺指标并非自动质量差 |

## 10. SQ1.1～SQ1.5 建议及Core-02风险

1. **SQ1.1 契约消歧与测量准备**：仅在用户授权后，优先 `skills/career/candidate-profile-interview/SKILL.md`（多资产/单目标stop）、`resume-review/SKILL.md`（来源不限定Profile）、`resume-composition/SKILL.md`（既有会话能力边界）、`resume-tailoring/SKILL.md`（Host预算措辞），必要时其余两Skill共享v2措辞；配套 `tests/unit/p47a-agent-capability-contract.test.ts`、`skillsQualityV1.test.ts`。仅删歧义/重述，禁止预先许诺质量提升。任何文本变更新版本/SHA，旧baseline JSON/fixture/证据不覆盖；新候选基线或versioned overlay另记。`src/ai/prompts/claimSafetyV2.ts`仅在发现明确措辞不一致时列入独立审阅，不改Guard。
