## 实际改动与业务链

生产仅三文件：`AgentTailoringInlineDiffs.tsx` 传递现有会话快照；`AgentArtifactContent.tsx` 在对话卡片和产物卡片共用的审核记录中展示岗位要求描述、来源引用、原始出处/文件页码、支持类型、当前审核状态和缺失来源提示；`agentToolService.ts` 在幂等重放时使用原不可变回执的完成时间，继续全部写后回读及载荷一致性校验。

测试新增 `jd03EvidenceReview.test.tsx`、`jd03TailoringIsolation.test.ts`；现有 `hermes-p46h-integration.spec.ts` CASE L 增加确认前零岗位分支、证据详情截图、刷新后完整分支一致性与A4截图。无新依赖/表/Runtime/Planner，未修改 Guard、Claim Safety、Schema 或六 Skills。

实际主链：确认来源通用简历 → 已保存岗位 → 共享 Fit → Hermes 高层 Tailoring Facade → 结构化提案 → 逐项查看来源并审核 → Host 最终确认 → Repository 原子派生独立岗位分支与正式 Revision → 刷新恢复该分支 → A4 → 正式 PDF。采用文字不反写 Profile。部分采用由现有逐项选择实现；“暂时跳过”可用上一条/下一条保留待审，不新增持久化 skipped 状态。未经处理的提案不能通过最终审核提交。

## 正式写入边界与幂等根因

提案/暂存选择不写正式简历；正式写入必须经 Host 确认及 WorkspaceRepository。既有 CAS 检查 Profile、来源分支/Revision、Job 版本，事务保留 sourceBranchId/sourceRevisionId，不同岗位分支相互隔离。测试同时检查原通用简历及完整 Profile 不变。

新测试复现：同 operationId 再次确认时，Repository 返回原 Revision，但服务重新计算 completedAt，保存不可变回执报 `resume_artifact_receipt_immutable_conflict`。修复只复用已有完成时间，未绕过回执内容一致性；测试断言重复 Revision ID、Revision 数量和整个回执均不变。数据库关闭重开后分支和 Revision snapshot 完整一致。拒绝/未审核提案即便被调用方塞进 selectedDiffs 也不会正式写入。
