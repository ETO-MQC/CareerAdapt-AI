# P4.8b Template & Presentation System 架构审计与实现边界

日期：2026-09-11  
状态：P4.8b 审计、实现与验收记录

## 1. 范围与不变量

P4.8b 只负责简历模板、展示配置、模板中心、预览、分页和 PDF 表现层。Career Intelligence v1、Resume Schema v2、Fact Guard、ResumeRevision、WorkspaceRepository、通用简历与岗位分支隔离均不在本阶段重做。

唯一渲染链保持为：

```text
ResumeRevision
  -> ResumeRenderModel
  -> Template Registry
  -> PresentationConfig
  -> Preview / Pagination / PDF
```

模板切换只能改变 presentation state。它不能生成新内容、修改事实、创建 ResumeRevision、写回个人资料库，也不能触发 AI/OCR/导入流程。预览和 PDF 必须使用相同的 render model、template、resolved presentation config 和 pagination snapshot。

## 4. Template Registry 契约

每个 definition 必须包含：

`id`、`name`、`shortName`、`description`、`category`、`layout`、`atsLevel`、`suitableRoles`、`tags`、`capabilities`、`defaultPresentationStyle`、`version`、`status`、`render`、`renderThumbnail`。

registry 是唯一目录来源。`TemplateIdSchema` 必须与 registry id 集合双向一致：每个 registry id 都可被 schema 接受，每个 schema id 都能在 registry 找到 definition。未知运行时 id 继续快速回退到现有安全模板，历史配置不因新增模板失效。

保留四个现有模板并新增两个真正不同的表现主题：

| id | 目标人群 | 布局 | ATS 元数据 |
| --- | --- | --- | --- |
| `classic-technical` | 技术、数据、研究、产品 | 单栏 | high |
| `modern-operations` | 运营、产品、项目管理 | 双栏 | medium |
| `ats-minimal` | ATS 优先、通用岗位 | 单栏 | high |
| `business-consulting` | 商务、金融、咨询、管理 | 双栏 | medium |
| `campus-clean` | 学生、实习、校园、应届 | 单栏 | high |
| `professional-classic` | 国企/行政/综合管理/传统企业 | 单栏 | high |

“high/medium”是内部可读性元数据，不是外部 ATS 认证、分数或通过保证。至少四套模板为高可读单栏；所有模板继续禁止 canvas、图片化正文、复杂 reading order 和关键浮动装饰。

## 5. PresentationConfig 解析规则

持久化 schema 继续使用现有 `ResumePresentationConfig`，不增加 Dexie 表，也不把自由 CSS 暴露给用户。概念解析为：

```text
ResolvedPresentation = TemplateDefaults(templateId) + UserOverrides
```

由于现有配置以完整受控 token 存储，P4.8b 用“与来源模板默认值比较”的兼容迁移语义识别覆写：仍等于来源模板默认值的字段切换到目标模板默认值；用户明确改过的字段保留。section override 是已有用户展示选择，切换时保留。reset 只写入所选模板的 default presentation style，不改变 content、order、hidden ids、revision facts 或 profile。

受控可见设置保持聚焦：模板、密度、字号、行距、页边距、section spacing、item spacing、accent；低频项放入“更多排版设置”。不引入 style framework、CSS DSL 或 generic layout engine。

## 6. 中文与内容完整性

六个 renderer 必须对同一 model 保持 identity、education、work、internship、project、skills、certificates、awards、custom 等 section/item，不得因为模板不熟悉某字段而静默丢弃。测试夹具覆盖中文/英文混排、长组织名、标点、日期范围、技术名、URL、email、phone 与长 section title。长文本允许自然换行；日期和 header 不得把主体挤出 A4；PDF 文本仍可选择和复制，链接保留。

模板差异来自明确的 section order、header、单/双栏布局、标题层级、规则线和受控间距，不通过换色复制同一个模板。分页、测量、coverage attributes 和 PDF 生成不进入 template-specific code。

## 7. Template Center 与验收

Template Center 仍从唯一 registry 读取 cards。card 展示真实 thumbnail、名称、短描述、可读性 badge、单/双栏、角色 tags；筛选保留 All/ATS/Single/Two/Technical/Business，并补充有真实候选主题的 Campus/Entry-Level 入口。它不是 marketplace，也不做 AI 选模板。

预览中切换模板只更新展示 state，不能 reload、调用 AI、重新生成内容或创建 Revision；相同 model 的内容快照必须保持不变。模板卡与 select 走同一 update handler，保存经过 WorkspaceRepository，失败时恢复原展示 state。

缩略图必须调用真实 `template.renderThumbnail`，而不是另画一套示意图。Preview 和 PDF 继续共享 renderer 与 pagination snapshot；导出 acceptance 至少覆盖 ATS、Campus、Professional 三类，并对六套模板检查页数、无裁剪、无重复 header、无内部 debug label、中文可选择、链接保留。

## 10. 实现结果与边界复核

### 10.1 代码拆分与规模

- `templateRegistry.tsx` 保留为 2 行稳定公开入口；唯一目录位于 `registry.tsx`，包含六个 definition、元数据、筛选、兼容性和真实 thumbnail renderer。
- `types.ts` 74 行，`presentationStyles.ts` 190 行；`shared/canonical.tsx` 257 行、`shared/legacy.tsx` 115 行。六个 renderer 文件合计 167 行：旧四套 renderer 保留表现语义，`campus-clean` 与 `professional-classic` 提供真实的 section order、header、规则线和单栏排版差异。
- 模板目录/类型/样式/shared/renderer 区域共 1,039 行，相对原 1,000 行集中 registry 为 `+39`；这个数字包含新增的两个主题与显式边界。不以机械行数宣称“重复减少”，实际重复的 canonical header、section/item、skill/language、coverage attributes 和 legacy fallback 已各自只有一个共享实现。
- 本轮变更的生产 `src` 行数按文本行统计为 `+1,229/-1,013`，净 `+216`；其中 CSS、工作区控件、卡片可读性和 schema/诊断契约的必要调整合计净 `+177`，模板区域净 `+39`。
- 没有复制 Reactive Resume、JSON Resume 或其他外部项目的实现代码；外部审计只采用架构边界和 QA 思路。若未来直接引入代码，先保留其版权和许可证声明。

### 10.2 PresentationConfig 语义

- 模板切换走同一个 `updatePresentationTemplate`，保存仍经过 `WorkspaceRepository.saveResumePresentationConfig`；先更新本地展示状态，保存失败恢复原状态，不创建 ResumeRevision，不改变内容、Profile、分支、事实或 order/hidden ids。
- `resolveTemplateSwitchStyle` 用来源模板默认值识别完整受控 token 中的用户覆写：未覆写字段采用目标模板默认值，显式 accent、字号、行距、密度、页边距和 section override 保留；模板 reset 只恢复当前模板默认排版。
- Preview、pagination、PDF HTML export 继续使用同一 `ResumeRenderModel`、template renderer、coverage attributes 和 pagination 实现；没有第二个渲染引擎、分页算法、catalog 或数据映射管线。

### 10.3 验收结果

- registry/schema 双向一致、默认值/覆写、coverage 与分页相关 Unit 通过；四个无 PII fixture × 六个 renderer 的 section/item coverage 为零丢失、零重复。
- `pnpm test`：194/194 files，1329/1329 tests；`pnpm typecheck`、全量 lint、`pnpm build` 和 `git diff --check` 取得完整退出码 0。
- 当前真实 UI 流程的 P4.8b acceptance：同一脱敏简历连续切换六套模板，内容 source-id signature 不变、无 navigation、无 model-facing request；六套模板逐一导出 PDF，页数均为 1–2 页，中文文本可选，且没有“模板中心”或编辑控件文案。
- 修改前/后桌面基线保存在 `artifacts/p4-8b-before-*` 与 `artifacts/p4-8b-after-*`；已检查 1024×768、1280×800、1366×768、1440×900、1920×1080。未进行全站视觉重设计。
- 相关历史 Agent E2E 仍有旧流程契约断点：`run-experience-match` 不存在于当前 `/jobs` 的“选择生成方式”流程，另一个 direct-PDF 历史路径被旧浮层遮挡。本阶段没有通过 skip、删除断言、放宽阈值或修改岗位/Agent 业务来规避；独立当前流程 acceptance 已覆盖本阶段模板功能。

### 10.4 最终决策

P4.8b 代码路径、模板中心、Preview/PDF 一致性、中文混排、分页和脱敏浏览器验收均已达到可交给用户进行视觉验收的状态。真实 Provider、主观内容质量和历史 Agent E2E 契约不属于本阶段模板实现的通过条件。
