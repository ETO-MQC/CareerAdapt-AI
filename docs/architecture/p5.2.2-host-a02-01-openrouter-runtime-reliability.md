## 重复执行根因与限定修复

锁定 `use-gateway-request.ts` 会在连接关闭后重连并再次 `request`；`submit.ts` 会在提交超时后 resume 并再次 `prompt.submit`。UUID、optimistic id 和前端单飞锁没有提供服务端恰好一次保证。故障 fixture 在服务端独立累计接收及执行次数，修复前 ACK 丢失、响应 delta 后断连、超时三项均执行两次。

修复只通过 `scripts/p522-host-a02-01-patches.mjs` 与已有 Renderer integration runner 的内存变换生效：

- prompt.submit 的重连移到调用原生 transport 之前；调用后遇到断连、超时、Abort 或含义不明确的连接错误，进入 UNKNOWN，不再次调用。
- 超时不再使用 Session 恢复重发；明确 Session not found 拒绝仍保留原有一次恢复。原生明确 session busy 拒绝的有界等待逻辑未改。
- 原有消息模型显示明确 UNKNOWN 错误，清除 busy/awaiting，保留用户消息；带 UNKNOWN 的会话阻止后续自动 queue drain。提示用户检查历史后再继续。
- 精确原始归一化 SHA 和唯一锚点均要求匹配；已打补丁或源文件漂移时快速失败。raw 原始 SHA、补丁后 SHA、十处最终变换记录及快照均保存。

修复不是服务端幂等协议，也不保证重启后的 UNKNOWN 持久化；没有新增 Session Store、Gateway 协议或任何 Python/Main/Preload 修改。完整原生会话重载、人工恢复、ACK 后流中断、晚事件隔离仍需要实际 Electron 资格验证。

启用方式为现有 `--careeradapt` 加本轮 `--reliability` 参数。省略 `--reliability` 保持旧 integration 行为；`optIn=false` 完全不启用 integration 变换。此补丁尚未通过真实 Shell 门禁，不宣称生产默认修复或发行通过。

### 故障证据

每个场景分别运行未补丁与补丁版本，共 10 项：

| 场景 | 修复前执行次数 | 修复后执行次数 | 修复后结果 |
|---|---:|---:|---|
| 发送前连接不可用 | 1 | 1 | 调用前安全恢复，仅一个实际帧 |
| 服务端接受，ACK 丢失 | 2 | 1 | UNKNOWN，不重发 |
| 已执行且发出 delta，随后断连 | 2 | 1 | UNKNOWN，不重发 |
| 接受后等待超时 | 2 | 1 | UNKNOWN，不 resume 重发 |
| 明确 Session not found | 1 | 1 | 首次拒绝未执行，恢复后执行一次 |

L2 的 React effects、atom 和 submit 业务依赖使用确定性测试适配器；JSON-RPC pending/timer、真实本地 WebSocket、两个锁定 hook 函数体是实际实现。它不覆盖整个 React 页面、Python Provider 或真实 Stop。账本包含 transport 调用次数、实际帧数、接收/执行次数、ACK、Session/message id、最终消息与 busy/awaiting。
