# P4.6f Hermes Delegation Architecture Decision

日期：2026-09-02  
状态：Implemented / deterministic validation complete / real-provider acceptance blocked by provider authentication

## Decision

Hermes is the sole production semantic agent. CareerAdapt remains the product
host, deterministic career domain, MCP boundary, persistence owner, and UI
projection layer. No new custom agent architecture is introduced.

The production flow is:

```text
CareerAdapt Conversation/Host
  -> POST /v1/runs
  -> Hermes run events (SSE)
  -> Host-safe event normalization
  -> CareerAdapt persistence and UI projection
```

Hermes owns model inference, semantic planning, model/tool choice, MCP
invocation loop, provider behavior supported by Hermes, and the final
assistant response. CareerAdapt owns facts, authorization, transactions,
workflow checkpoints, confirmations, artifacts, attachments, history, and
rendered previews.

## Before and after ownership

Before, production composition exposed two semantic harnesses:

```text
UI
  -> AgentRuntimeProvider
  -> AgentRuntimeRouter
       -> NativeCareerAgentRuntime
            -> AgentKernel -> AgentExecutor / HttpAgentModel
       -> HermesCareerAgentRuntime
            -> bridge -> Hermes model/tool loop/MCP
```

After, production composition has one semantic route:

```text
UI
  -> AgentHostStore / AgentRuntimeProvider
       owns persistence, UI state, deterministic transitions,
       confirmations, workflow checkpoints, artifacts, and history
  -> thin HermesCareerAgentRuntime
       -> CareerAdapt bridge -> Hermes `/v1/runs` + event stream
            owns model inference, tool selection, MCP loop, final response
  -> CareerToolGateway / MCP / WorkspaceRepository
       owns Career domain authorization and atomic writes
```

`AgentExecutor` remains as a domain-side executor behind the Career gateway;
it is not a second production semantic model loop.

| Responsibility | Decision |
| --- | --- |
| Model inference, semantic planning, model retries/fallbacks | Move to / keep in Hermes |
| Tool choice and MCP loop for official Runs | Move to / keep in Hermes |
| CareerProfile, Job, Resume, Tailoring, Fact Guard, structural integrity | Keep in CareerAdapt |
| Repository writes, receipts, authorization, confirmations | Keep in CareerAdapt |
| Conversation persistence, attachments, artifacts, history, preview | Keep in CareerAdapt |
| One `/v1/runs` start and event stream | Keep in thin Hermes client |
| One same-run transport reattach | Keep in thin Hermes client |
| Local heartbeat/watchdog repair, semantic retry, Run replacement | Delete from production semantic path |
| Manual `executeToolCall`/callback/model loop | Legacy adapter only; never official Runs |
| Native semantic fallback | Delete from production composition |

## Runtime and session rules

- A normal new conversation is a Conversation Session plus a User Turn. It has
  no `taskState` or `workflowState` until Hermes invokes a Career workflow
  facade or the user explicitly starts a deterministic Career action.
- Existing persisted workflow sessions remain migration-compatible, but their
  compatibility shape does not create a workflow for new conversations.
- One user message creates at most one semantic Hermes Run. An interrupted
  event stream may reattach to the same Run once; it never submits the same
  semantic turn to Native or starts a replacement Run.
- `AgentRuntimeRouter` is a thin event adapter. It does not select a fallback,
  retry semantics, execute tools, or re-prompt the model.
- `turn_failed` triggers at most one authoritative `GET /v1/runs/{runId}`
  readback. Diagnostics are allowlisted to run/status/provider/model/status
  code/error type/category/message category/failure layer/tool/event fields;
  raw secrets and full prompts do not cross the boundary.

The bounded failure vocabulary is:

```text
provider_auth | provider_request_invalid | model_not_found
tool_schema_invalid | context_overflow | provider_timeout
mcp_tool_failure | hermes_internal_failure | transport_failure | unknown
```

A Run failure is scoped to the turn. If process, API, provider, Career MCP,
and tool-surface readiness remain true, global Agent Ready remains Ready and
the conversation shows `本轮回答失败。当前对话已保留，你可以重试。`.

## Prompt and tool policy

The base `careerRunInstructions` is short and stable: answer ordinary
conversation naturally, use CareerAdapt MCP only when saved Career facts or an
explicit Career action is needed, never invent facts, and never claim a write
without a CareerAdapt receipt. Active workflow/checkpoint constraints and
attachment hints are appended only when relevant.

Tool selection is model-driven. The host does not pre-read Profile, Resume,
Job, or runtime status before Hermes asks. `你好` therefore has zero expected
Career tool calls. A read-only Career question may cause a read-only tool; a
JD tailoring request may cause the high-level tailoring facade. Prompt text is
guidance, not authorization. CareerAdapt's gateway remains the server-side
authorization boundary.

The official `/v1/runs` route does not pass CareerAdapt callback contracts as a
second local tool loop. Hermes' registered MCP surface and native per-run
capabilities remain the source of truth; the existing small Career MCP surface
is retained rather than adding a custom dynamic tool protocol in this phase.

## Validation scope

Added/updated deterministic coverage includes plain conversation, no workflow
shell, tool-free greeting, official Run lifecycle, one terminal readback and
safe category mapping, same-Run transport reattach, no Native fallback, Run
failure versus global Ready, session migration/rebind, MCP/legacy compatibility,
deterministic checkpoints, and the existing P4.6b tailoring path. Full command
results are recorded in the final delivery report; real-provider acceptance is
not closed while the configured provider returns HTTP 401.
