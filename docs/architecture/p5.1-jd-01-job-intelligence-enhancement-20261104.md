## 根因与数据变化

1. 旧词法层按行创建来源单元；旧语义层只能对该单元分类，不能把长段落编译为多个要求。
2. 实际模型契约是 compact `unitAssignments`，不是完整 `requirements` JSON。`JdAnalyzerModelOutputSchema` 原本没有 requirements 字段。旧页面 `requirements: []` 容易误导，但不能把这一行单独描述成丢弃当前有效 requirements 数组。真实缺口是模型无法表达多条来源内要求，且页面只能传入整单元 assignment。
3. 标题主要依靠固定词表，未知栏目容易成为要求，或继承前面的栏目。显式 all_of wrapper 未进入正式 groups。匹配 recall/evaluation 使用 includes，Java 会命中 JavaScript。
4. 正式岗位选中状态只存在 React state，提交后刷新默认选中第一个演示岗位。首次浏览器验收复现：IndexedDB 中合成岗位完整、页面却展示另一岗位，甚至数量恰好相同；因此增加内容和来源断言，不能只验数量。

现在原始 lexical unit 保持按行、完整 rawText 保持不变。先识别栏目、列表、父子/组关系，再对无父子/条件分组的顶层要求保守分句。每个独立谓词句有精确 SourceSpan、稳定 ID、原段落 originUnitId/originSpan 和原始 lineNumber。多短句、例子、共同限定条件不机械拆分；any_of 中含多句的一个选项仍是一个选项。原 B 的“段落仍是一个 lexical unit”诊断断言保持并通过，语义层另有多节点测试。

## AI 到正式数据链

`raw JD / JobSnapshot → 本地 provisional ledger → jd-analyzer 注册 Schema / coercion → assignment.segments → 来源与条件校验 → 本地子单元 ID → 原 reconcile / compileJobRequirementGraphV4 → projectJobGraphV4ToAnalyzerOutput → JobAnalysisDraft → 用户核对 → 原 conversion confirmation / WorkspaceRepository → JobDescription + RequirementGraph → JobsWorkspace`。

新增可选 segments，每段只提供相对于原单元的 UTF-16 start/end 和有限语义字段；正文与 ID 由本地创建。校验要求顺序、不重叠、不越界、完整覆盖所有非空白来源、不切开条件连接、不拆已有父子分组。无效拆分回退原单元并记录 source_inconsistency，不丢失来源。Schema 无效 assignment 记录错误；不存在 ID、重复 ID、遗漏来源及父子循环沿用原诊断。

AI exactKeywords 需要原文词边界支持；无来源关键词不进入 exactKeywords。semanticAliases 保留在 Graph，AI 语义覆盖和 AI 拆分通过已有 needsConfirmation 门禁待用户核对，不把模型置信度当用户确认，也不调整事实安全阈值。未经确认的新要求不会被 mapper 写入正式岗位。页面使用正式 Graph 的唯一投影，不显示原始模型 JSON；删除了伪造空 requirements 的中间对象。

## 规范化与条件

- ID 来自实际来源偏移与文本，重复同一语义拆分不追加节点；重复编译 Graph/ID/hash 相同。
- 可选 `keywordLogic` 同时贯通 Graph、Analyzer projection、JobRequirement、mapper 和匹配解释；旧快照没有该字段仍可读，无数据库迁移。
- “Java 或 Python”保留一个 any_of 技能要求；“Java 和 Spring Boot”保留一个 all_of 组合要求。显式组级 any_of / preferred_any_of / all_of 继续使用原 groups。
- 混合复杂逻辑保留完整原文，不伪造任意布尔表达式；无法安全拆分的条件留作原子要求核对。
- Java / JavaScript 在 Graph 技能识别和既有规则匹配 recall/evaluation 均用共享词边界。组合条件缺项不能因一个技术名的多个 token 获得 strong。
- matcherVersion 升至 evidence-matcher.v1.1，条件信息进入候选指纹；旧匹配按既有版本失效机制重新评估。

## 栏目、证据映射与 UI

在原规则上加入结构/语义线索，模型仍可对每个来源单元覆盖栏目。未知短冒号标题保留 heading 和原文，不静默删除；其后内容逐项判断，避免继承错误栏目。福利、公司介绍的明确栏目/内容不作为硬要求。标题识别不承诺覆盖全部自然语言表达。

继续复用 RequirementMatch 的 requirementId ↔ evidenceRefs 多对多关系，不另造事实/匹配表。每条记录已有证据 ID、factQuote 原始来源、factText、explanation、matchLevel、risks、rule/AI/manual 来源。新增合成测试验证两个要求分别引用两项经历，同一经历支持两要求；支持程度/缺口解释属于该匹配记录，未声称每条引用都有独立模型评分。

JobsWorkspace 从正式 job/Graph 显示数量、分类、重要性、原文、关联技能、条件关系、来源段落和精确位置，并展示已有匹配的理由、支持程度、证据及原始来源；未匹配/过期状态明确。资料库/简历来源切换清空旧显示，并按当前来源恢复匹配。未知栏目与未知类别要求保留可见入口。不做页面重构或设计系统调整。

选中岗位同步至现有 jobId URL 参数，刷新保持同一正式岗位。Repository 集成测试关闭重开隔离 IndexedDB，核对 rawText、Graph、ID、要求内容和幂等提交；React 真实组件渲染数量与存储 Graph 一致。生产浏览器测试另检验真实 UI 操作和实际 IndexedDB，不以浅 mock 替代持久化。
