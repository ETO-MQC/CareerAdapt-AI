# P4.6c Unified AI Runtime Configuration

## Scope

P4.6c makes the AI configuration path explicit from Settings to the running
Hermes process. It does not introduce a second runtime, provider abstraction,
Dexie table, or configuration database.

The existing `careeradapt-ai-settings` localStorage record remains the renderer
draft/desired input. `HermesSupervisor` remains the only process owner. The
existing `RuntimeStatusStore` remains the renderer status projection.

## Authorities and state semantics

| State | Authority | Meaning | May affect active Hermes status? |
| --- | --- | --- | --- |
| `AiRuntimeConfigDraft` | Settings form and `careeradapt-ai-settings` | User-editable values, including credential intent | No |
| `AiRuntimeConfigDesired` | Supervisor after staging a requested environment | The safe, fingerprinted configuration that should be applied | No, until verified |
| `AiRuntimeConfigActive` | Running Supervisor readback plus health/provider verification | The configuration actually accepted by the running Hermes instance | Yes |
| `CandidateProviderTestResult` | `/api/ai/test` response | An isolated probe of a draft | No |

`provider` is an identity such as `openai-compatible` or `openrouter`; it is
never an endpoint URL. `baseUrl` is the endpoint URL and `model` is the model
identifier. Diagnostics expose only safe credential state and config metadata,
never the API key.

The canonical fingerprint hashes normalized provider identity, base URL,
model, and the credential in memory. The credential is not serialized into a
receipt, snapshot, log, notification, or health diagnostic. A monotonic
generation accompanies a fingerprint so a readback can be checked against the
specific apply attempt.

## Apply transaction

`AiRuntimeConfigCoordinator` is the one renderer-facing sequencing boundary:

1. Normalize and validate the draft.
2. Optionally run `/api/ai/test` as a candidate-only operation.
3. Persist the desired draft to existing localStorage.
4. Stage the desired configuration in the Supervisor.
5. If a semantic Hermes run is active, return `deferred` without starting a
   new run. Settings performs the explicit stop/interrupt confirmation before
   an apply that the user approved.
6. Otherwise perform one controlled Hermes replacement/restart.
7. Read health from the running Hermes path, verify provider/model/fingerprint
   and generation where available, then commit `Active`.
8. Return a receipt containing `accepted`, `applyStatus`, desired/active
   fingerprints, `restartPerformed`, `verified`, `rollbackOccurred`, and a
   safe reason code.

The visible apply states are `idle`, `validating`, `testing`, `saving`,
`restarting_runtime`, `verifying`, `applied`, `deferred`, `failed`, and
`rolled_back`. A maintenance deferral is therefore not silently represented
as a successful save.

Repeated Save & Apply requests share the coordinator's in-flight operation.
The Web route and Electron IPC adapter only translate transport; both call the
same Supervisor semantics and return the same safe receipt fields.

## Rollback

When a previously healthy active configuration exists, a new configuration
that cannot reach provider readiness (for example 401/403, invalid endpoint or
model, protocol mismatch, or provider unreachability) gets one bounded
rollback. The previous environment is restarted once and read back again.

On success, the old configuration is `Active` and Ready, the receipt is
`rolled_back`, and the failed new Desired draft remains in localStorage and in
the runtime snapshot so the user can correct it. Rollback does not recursively
retry the failed candidate or create a restart loop. If rollback itself cannot
be verified, the result is `failed` with `config_rollback_failed`.

## Credential intent

An empty API-key input is not treated as a destructive clear. The draft carries
one of:

- `unchanged`: preserve the already effective credential when the key is not
  shown to the renderer;
- `replace`: apply the newly entered key;
- `clear`: explicitly remove the managed provider credential.

Server-environment credentials are displayed as configured/not configured and
are never hydrated into the form. After a verified apply, Settings hydrates
non-secret fields from Active and keeps the local key only when its source is
managed and the user has not started editing it.

## Reconciliation and UI projection

Settings and Hermes Control Center consume the same
`HermesControlSnapshot.runtimeConfig.active`. They do not independently fall
back to localStorage, a candidate test, or a stale health response. A
fingerprint/generation mismatch is exposed as `configuration_desync` and can
trigger one bounded readback attempt.

The topbar reports `AI · Hermes · 正在切换模型` during the apply transaction.
Candidate failures are shown under candidate diagnostics while the active
provider/model/readiness remain unchanged. A rollback returns the old Active
configuration to Ready and reports the recovery notice.

## Codex concepts adopted

The design uses the same useful conceptual separation as a layered config
read/write protocol: expose effective values with their origins, and return a
versioned write result rather than treating “no exception” as proof of
application. CareerAdapt keeps its own Supervisor, storage, and domain
contracts; no Codex runtime or protocol is added. Reference concepts:

- [Codex config read response](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/src/protocol/v2/config/ConfigReadResponse.json)
- [Codex config write response](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/src/protocol/v2/config/ConfigWriteResponse.json)

## Verification coverage

Focused tests cover candidate isolation, canonical provider identity and
fingerprinting, Save & Apply single-flight behavior, validation before
persistence, Supervisor readback-gated apply, active-run deferral, Web/Electron
receipt behavior, stale diagnostic isolation, and one-shot rollback. Full repository validation is recorded
in `history3.md` for the delivery run; no real two-provider success is claimed
without configured provider credentials.
