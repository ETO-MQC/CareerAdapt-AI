# P4.6b Job Resume Tailoring Quality Closure

## 结论与范围

P4.6b 收口的是岗位简历定制的生成质量与安全边界，不改变 P4.6a 的 Resume Schema v2、WorkspaceRepository 写入、Review→Apply→Render 链，也不新增 Dexie 表、生产依赖、AI agent 或并行最终写入器。

当前 Canonical Agent 路径只有一个最终内容生成器：

```text
AgentHost / Career Workflow
  -> generate_changes
  -> BrowserAgentToolService.generateTailoringChanges
  -> generateTailoringDiffsCommand
  -> prioritizeTailoringTargets (最多 6 个目标)
  -> resume-tailor-diff (每个目标一个 typed diff)
  -> validateEachTailoringDiffLocally / dedupeTailoringDiffs
  -> diffReviews review ledger
  -> previewTailoringChangesCommand
  -> WorkspaceRepository.applyTailoringDiffs
  -> ResumeRevision / RenderModel / PDF
```

`resume-tailor`、`resume-tailor-batch`、`resume-optimization-planner` 和旧 `JobOptimizationPanel` 仍保留为兼容/历史调用面；它们不再是 Canonical Agent 的 P4.6b 最终写作者，本轮不扩展其旧 suggestion 语义。

## 责任边界

| 层 | 责任 | 明确不做 |
| --- | --- | --- |
| Hermes / Agent | 阶段推进、等待用户、调用工具、重试边界 | 不改事实、不直接写 Resume |
| Job Optimization | 解析岗位要求图、相关 requirement、证据候选、目标排序、问题计划 | 不替用户确认新事实 |
| `resume-tailor-diff` | 在一个目标字段内做语言改写 | 不返回整份简历、不决定是否可写入 |
| Domain quality gate | 原文快照、路径、类型、证据、所有权、指标、重复、禁用能力和语句质量 | 不调用 LLM critic，不放宽 Fact Guard |
| Review / Repository | 用户评审、确认、原子写入、Revision、结构与 Render 验证 | 不信任 transport `selectedDiffs` |

## 输入契约

### Requirement Details

`routeTailoringRequirements()` 从 canonical Job Requirement Graph 只投影当前目标的相关 requirement，最多 4 个。每个 `requirementDetails[requirementId]` 只允许包含该节点的有限信息：detail clauses、semantic aliases、hard constraint、parent group 和 evidence expectation。不会把完整 JD raw text 或无关 requirement 送入 writer。

### Evidence hierarchy

生成器看到的证据明确分为：

1. 当前目标的 direct resume evidence；
2. 相关 resume evidence；
3. 已确认 profile evidence；
4. 已确认的用户声明。

JD 文本、关键词命中和语义相似度只能说明“要求相关”，不能证明能力、数字、结果、工具或 ownership。verified diff 必须携带允许的 evidence refs；reasonable inference / user declared 仍要经过 Review/Confirmation。

### 用户回答

冻结的 clarification plan 完成后，回答以 `confirmedUserDeclarations`、`negativeUserDeclarations`、`uncertainUserDeclarations` 注入每个最终 writer 请求：

- 正向回答可以支持范围受控的 `user_declared` 表述，例如“使用 Claude Code 4 个月”，但不自动升级为熟练或主导；
- `没有/否` 的 Cursor 等回答进入 forbidden terms，禁止新增到 diff；
- 不确定和跳过不产生事实，也不被转换成正向 claim；
- 最终 generation 阶段不会再让模型创建新问题。

## 目标选择

`prioritizeTailoringTargets()` 使用确定性迭代评分，最多 6 个目标。分数由 requirement priority/relevance、direct/related/profile/user-declared evidence、经历具体性与 coverage need 组成，并扣除已覆盖 requirement、重复 keyword 和 summary redundancy。

项目、工作、实习等具体经历优先于泛技能；summary 只做综合 synthesis；skills 只作 support。每次选择后记录已覆盖 requirement/keyword，使结果在输入顺序不变时稳定且保持 section diversity。tie-break 使用 section/item/field 的稳定键。

## Writer Prompt 与重试

`resume-tailoring-diff.v4-quality-closure` 的 system prompt 与 structured payload 使用 `FACT`、`REQUIREMENT`、`CONTEXT`、`CONFIRMED USER DECLARATION`、`RETRY DIAGNOSTIC` 五个边界。`CONTEXT` 只保留职位标题、截断后的岗位信号、intensity 和有限 whole-resume projection（summary、相邻行、capability phrases、nearby item IDs）；不发送完整分支。

每个目标最多一次应用层 rewrite retry。retry 只携带安全 reason codes，例如 `mechanical_prefix`、`duplicate_original`、`truncated_output`、`responsibility_upgrade`、`invented_metric`、`generic_proficiency_sentence` 和 `insufficient_evidence`，并要求 materially different correction。模型返回 no-op 或证据不足时不强制重写；closed question phase 的 clarification 不会被静默当成新问题，而会记录 `insufficient_evidence_after_question_plan` diagnostic。

intensity 只影响改写的主动程度：conservative 最小表达调整、balanced 实质性重组、proactive 最强但可辩护的表达；三者事实标准、证据层级和 ownership 保护完全相同。

## Deterministic quality gate

现有 `CareerResumeQualityPolicyV1` 保留原 ID 并扩展为同一策略，覆盖 accomplishment-first、Context→Goal→Action→Method→Result/Verification、employer pain point、direct evidence 优先、ownership preservation、technical specificity、summary synthesis、skills support-only、no-change-needed、禁止 keyword stuffing/JD parroting。

`validateEachTailoringDiffLocally()` 在写入前继续校验 target/path/original/type/empty/no-op/截断/机械前缀/重复原文/指标/职责升级，并新增或收口：

- internal field labels、generic proficiency、malformed Chinese phrase；
- negative/uncertain user capability 与 proficiency upgrade；
- keyword stuffing 与 JD parroting；
- array 内重复句和跨 Diff conservative dedupe。

没有新增 ML/LLM critic，也没有改 Fact Guard 阈值。Apply 前再次使用同一安全 gate，Review ledger 仍是唯一可写入来源。

## 验收覆盖

`tests/unit/p46b-tailoring-quality.test.ts` 以 A–L 覆盖局部拒绝码、证据与回答约束、目标排序、跨 Diff 去重、Prompt payload 边界和 retry diagnostic。`tailoringCommands.test.ts` 覆盖：

- stale/rejected diff 一次 reason-aware retry；
- no-change-needed 不强制改写；
- negative Cursor 不进入生成结果；
- positive Claude Code 用户声明进入 bounded generation；
- Review accept/reject、preview 和 apply verification。

P4.6a 的 structural integrity、Repository、ResumeRevision、RenderModel、分页/PDF HTML golden 回归继续作为 Tailoring→Review→Apply→Render 的确定性下游门禁。

本轮没有配置真实 provider 的最终内容评审；因此当前结论是 deterministic contract / domain gate 已通过，real-model wording acceptance 仍需用户在配置 provider 的环境中确认。
