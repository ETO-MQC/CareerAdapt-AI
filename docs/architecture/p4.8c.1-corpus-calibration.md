## Delivered calibration

The existing `CareerResumeQualityPolicyV1` remains the single policy. Its instructions set truth/provenance/maturity/ownership → relevance → specific evidence → clarity → concision → polish. Deterministic contextual signals assist Review; they are deliberately conservative and cannot fully understand arbitrary prose. No rubric score is exposed to users.

| Dimension | Integration |
|---|---|
| action_clarity, method_specificity, outcome_evidence, content_specificity | `assessResumeBullet`: action, mechanism, concrete context and observable verification signals; optional dimensions alone never fail |
| bullet_atomicity | Existing rewrite diff recommends splitting explicitly independent achievements; Writer preserves punctuation within a causal chain |
| evidence_density, genericity_boilerplate | Contextual quality suggestion rather than positive-word blacklist; evidence-backed wording bypasses old mechanical-prefix false positives |
| role_relevance | One static resolver feeds existing Blueprint relevance and both Writer/Tailoring prompt contexts; compiled item order now follows Blueprint order |
| tech_stack_redundancy | Long ungrounded catalogs get a deduplicate suggestion; project stack rows use the existing eight-tool compact limit, while source facts and proof remain intact |
| section_redundancy | Existing dedupe plus identical Summary/proof detection; Skills index + project mechanism is legitimate |
| page_utility | Existing targetPages/estimatedPageCount; generic Summary under pressure is a removal proposal, not a mutation; no warning for page count alone |
| strong_content_preservation | KEEP_STRONG = no diff; strong Chinese mechanism bullets survive both Writer and repair pass |
| metric_verifiability | Existing Fact Guard blocks generated unsupported precision; Review emits existing verify diffs for user-origin unsupported precision without deleting the original |

Composition omits automatic school/skill recap Summary. AI may supply a useful evidenced positioning Summary; generic or repeated summaries are not accepted. Selection still uses existing evidence graph eligibility, scores, asset caps and page-budget architecture. No new role writer, schema, service, table or agent was added.

Review uses the existing ledger vocabulary: KEEP_STRONG is no-op, TIGHTEN is shorten, REWRITE is rewrite, VERIFY is verify, DEDUPLICATE is deduplicate, REMOVE_CANDIDATE is remove proposal. No update_existing/revision/write contract changed.

Role confidence: AI/LLM/Agent/RAG HIGH; backend/frontend/infrastructure MEDIUM; product/data/growth PROVISIONAL; unsupported or unrecognized targets receive generic guidance. These are [INFERENCE] preferences grounded in the package's [CORPUS]/[HELD-OUT] scope, never hard templates. AI categories are optional evidenced emphasis; AI effectiveness claims without evaluation support get a verification suggestion, and architecture catalogs without contribution get a rewrite suggestion.

Tailoring retains its existing deterministic hard guards and closed question plan. The prompt now explicitly preserves strong content, optional Summary/metrics/formula/page count, index/proof repetition, and evidence before brevity. Backend preference explicitly retains AI facts and reprioritizes relevant service/data evidence. The existing task registry adds only the resolved preference to presentation context.

Writer boundary audit also found `skillEvidence` was absent from the strict task input contract. Its existing maturity/evidence-count information now travels through the existing instructions field, validated by an actual WritingService request test; no task schema extension was needed.
