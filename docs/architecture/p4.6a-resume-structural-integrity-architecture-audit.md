## P0 implementation boundary

- `src/domain/resumeIntegrity/ResumeStructuralIntegrity.ts` classifies `healthy`, `legacy_flat_projection`, `degraded_structured_item`, and `unrecoverable` items. It deterministically recognizes labeled project/work/education forms and compact education projections, rehydrates only existing facts, normalizes narrative skills through the existing technical-term taxonomy, and fails closed for ambiguous skills or non-deterministic missing identity.
- `src/services/storage/repositories.ts:260` now makes `syncStructuredContentItems()` inspect every item, rehydrate recoverable items, replace the legacy mirror with a clean semantic projection, and reject unrecoverable content before Job derivation or persistence.
- `src/domain/resumeIntegrity/tailoringStructuralPreservation.ts` asserts identity and structural fields across source/result branches. Tailoring remains field-patch based; no whole-resume AI replacement was added.
- `src/domain/resumeFields/catalog.ts` is the shared labeled/compact parser boundary. Project organization, URL, tools, background, dates, role, highlights, and outcomes remain typed.
- `src/domain/resumePresentation/projector.ts` applies sentence-level semantic dedupe. Project URLs remain links, while inline metadata is limited to organization and tools.
- `src/domain/resumeRender/mapper.ts` repairs structured items transiently for rendering. Old source-only legacy items without labels retain compatibility rendering; the repository write/derivation boundary remains fail-closed.
- `src/domain/branch/targetRole.ts` centralizes safe target-role extraction. Job title, explicit JD title, snapshot role/title, and generic fallback are ordered without accepting conversational wrappers.

## Safe consolidation plan (not implemented in P4.6a)

### P1 — Host strangler

1. Freeze public Host APIs and add characterization tests around turn start, workflow answer, confirmation, retry/regenerate, and terminal events.
2. Route lifecycle ownership through the existing `TurnController` (`idle`, `pending_start`, `running`, `waiting_for_user`, `interrupting`, `completed`, `failed`). Keep compatibility projections temporarily.
3. Make `WorkflowInteraction.kind` carry clarification, confirmation, approval, review, and choice reasons. Hermes `waiting_for_approval` remains runtime telemetry, not a second product turn state.
4. Extract behind existing boundaries in this order: `tailoringWorkflowDriver`, Resume Composition coordinator, Profile Intake supervisors, then message/branch modules. Keep `AgentHostStore` as a façade until each extraction has characterization coverage.

### P2 — Bridge ownership

Introduce a small `CareerDomainBridge` transport contract with Browser HTTP and Electron IPC implementations. Keep Browser HTTP supported for Web/dev; make packaged Electron IPC the primary lifecycle transport where available. Move long-lived packaged ownership away from renderer page lifecycle incrementally. Do not move IndexedDB Repository ownership or add a Dexie table in this plan.

### P3 — Runtime, diagnostics, and `runTurn`

- Mark Hermes as the explicit production semantic runtime and Native as explicit deterministic/test/compatibility runtime; retain bounded, observable same-runtime recovery and prohibit silent semantic fallback.
- Keep the legacy Hermes adapter compatibility-only and instrumented. Delete it only after supported transports guarantee official Runs.
- Extract `prepare`, `start/reattach`, `stream`, `status/recovery`, `terminal projection`, and `cleanup` phases from both large `runTurn` methods. First add one shared terminal-normalization characterization suite.
- Change the MCP diagnostic path to compute a safe size bucket without repeated full serialization, or gate the expensive trace behind diagnostic mode. Preserve MCP response semantics.

No P1/P2/P3 architecture extraction was performed in this round.
