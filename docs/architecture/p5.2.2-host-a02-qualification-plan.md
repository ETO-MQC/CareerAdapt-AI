## 4. A-02-01 Provider、Streaming 与 Stop 审计

### Provider 配置与选择

原生引导支持 API key、OAuth 类入口与 local/custom endpoint。saveOnboardingApiKey 保存后可绕过 runtime gate；“配置已保存/引导已关闭”不能证明密钥有效或模型可请求。custom 路径不是单设 OPENAI_BASE_URL：saveOnboardingLocalEndpoint 探测模型并通过 `/api/model/set` 保存 provider=custom、base_url、model、可选 api_key。`hermes_cli/runtime_provider.py` 解析运行时身份；model.options/session.info 向 UI 反馈实际模型/provider，配置默认值与已有会话 override 需分别比较。切换失败需验证原生回滚与错误显示，不跨会话偷偷改变执行身份。

| 方案 | 前置条件 | 可证明范围与限制 | 决策 |
|---|---|---|---|
| A 已授权远程测试 Provider | 用户明确 endpoint/model/付费额度/允许传输的合成内容及凭据来源 | 可测真实服务 stream/tools/vision；受网络、限流、账户能力影响 | 能力齐全且授权后优先作为端到端基准；当前未确认可用 |
| B 本地 OpenAI-compatible | 已安装、已启动且授权使用的服务；`/v1/models`、stream、所选模型 tool/vision 能力核实 | 真实本地推理可算 L4，但不证明远程上传；兼容接口不保证函数调用或视觉 | 隐私测试候选；不得自动下载模型/启动未知服务，当前未确认可用 |
| C 锁定 Hermes 中其他 Provider | runtime_provider/model catalog 实际支持、独立凭据/CLI或OAuth已授权 | 可能有不同 transport、工具由外部 runtime 执行、事件语义不同 | 单独能力表；不把其他 transport 的通过转授 Python tool dispatcher |

离线127.0.0.1:9不是本地模型，也不是方案 B；合成 HTTP/WS stub 只能作 L1/L2 故障控制，不能称真实 Provider。当前不查看用户 `.env`、auth store 或现有 Provider 凭据，不探测 endpoint 是否在线。

### 十步链与确定的风险

1. Composer sanitize → per-target busy / `_submitInFlight` 锁 → 单一 optimistic user id。
2. 固定会话/路由上下文，必要时 create/resume；同步附件后发送 prompt.submit，RPC ACK streaming 与首 Token 是两件事。
3. AIAgent 的 Provider transport 返回增量，server `_stream` 发 message.delta（message.start 不是首 Token）。
4. gateway-event 转交 appendAssistantDelta；index.ts 定时 flush，最终 complete 先 flush，interim 独立封口，避免工具插入打乱文本。
5. tool.start/progress/generating/complete 经 session id 路由到 per-runtime cache，不能用当前 UI 的 session id覆盖后台事件。
6. message.complete 合并最终文本并清 busy/awaiting；历史 hydration 与 sidebar 刷新不等于再次执行模型。
7. Provider/agent init 错误发 error，经 failAssistantMessage 清 pending/提示；有专门 terminal-error-frame、agent-init-error 测试源码。
8. 网络中断：shared client pending reject/timeout；请求 hook 存在重连再调用，需额外认证“不重发未知结果”。
9. Stop 在 Renderer 标记 interrupted，原生 session.interrupt → agent.interrupt；后到 delta/tool 受 interrupted guard 限制。
10. Runtime 设置 `_turn_cancel_requested`、清 queued_prompt/pending；正常线程最终清运行状态。Stop 明确保留用户启动的后台进程，不应把它们全部杀掉。RPC AbortSignal 只取消等待不代表 Provider/工具已取消。

补充后端网络链：`run_agent.py` run_conversation转入`agent/conversation_loop.py`，chat-completions参数/响应由`agent/transports/chat_completions.py`适配，流执行在`agent/chat_completion_helpers.py:2294` interruptible_streaming_api_call。该实现登记per-request stream handle并在中断时尝试close；这证明有资源释放实现，不能证明任何Provider服务端已停止计费。conversation_loop调用`_execute_tool_calls`后携带tool role结果继续模型循环。非chat-completions transport需另验，不把这一链泛化到所有Provider。

**源码确认的重发路径，运行后果尚未复现：** use-gateway-request.ts 对 `not connected|connection closed` 重连后再次 request；submit.ts 对 session not found **或 timeout** resume 后再 prompt.submit。内存 submit lock 和 optimistic 去重不能证明服务端恰好一次执行。A-03 前应禁止未知 ACK/未知执行结果自动重发。最小候选是 Renderer 精确虚拟补丁：对有副作用的 prompt.submit 断连/timeout保留 UNKNOWN，先只读查状态；仅明确“未接收/未执行”的拒绝允许再次提交。不得对所有方法一刀切或修改上游磁盘/runtime。若读接口不能消歧，停止并报告协议缺口，不伪造 request id 幂等保证。

指标：记录 t_click、t_rpc_send、t_ack、t_first_delta、t_first_paint、t_complete、t_stop、t_interrupt_ack、t_settled，使用单机单调时钟并区分进程时钟。10个正常短轮报告 TTFT/总耗时 p50/p95，Provider 环境写明；不设置伪通用模型速度阈值。增量至少3次非空 delta/两次完成前 paint；最终文本与按序 delta/interim/final 对齐，无重复用户/助手行。Stop UI 在500ms内反馈，interrupt ACK目标2秒、settled目标5秒，超出单独记失败/Provider限制；之后观察10秒无追加UI文本，无新工具执行。故障后下一轮可发送、busy/awaiting/pending复位；请求/工具 ledger无未知结果自动重发。数值为后续拟定门禁，未测。

## 5. A-02-02 Native Tool Activity 审计

必须分别证明：①真实模型响应携带工具意图；②Hermes解析 name/arguments/tool_call_id；③原生 dispatcher 调用 handler；④handler 输出确定结果并形成 tool role 消息；⑤第二次模型请求包含该 tool_call_id/result；⑥最终 assistant 完成且 UI idle。工具图标或 `tool.complete` 本身不代表⑤⑥。

事件结构：tool.start 含 tool_id/name/context，详细参数受 verbose 条件控制；complete 含 tool_id/name/args/result，可附 duration_s/summary/result_text/inline_diff；原生结果可能是 JSON 或字符串。发事件受 `_tool_progress_enabled` 等原生 gate 控制，测试需显式配置原生显示选项，不能注入虚假事件替代执行。

锁定 `hermes_cli/plugins.py` 的 PluginContext.register_tool 委托原 registry；可复用测试隔离插件机制，**不把 pytest monkeypatch registry 当真实 Provider 执行**。目前未证明已有合适的无副作用固定输出生产工具。推荐仅在独立 HERMES_HOME 安装测试插件 `a02_qualification_echo`，schema限定 `{value: "A02_SYNTHETIC"}`，返回固定 `{ok:true,value:"A02_SYNTHETIC",checksum:"fixed-v1"}`；handler不读写文件、不访问网络、不连接 CareerToolGateway/Repository、不读环境密钥。执行次数由 harness/原生事件在进程内记录，导出日志由测试 harness 完成。只允许该工具；其他原生工具在测试配置中关闭，测试后保留原配置不动。此插件尚未编写，若锁定插件 allowlist/装载无法实现隔离则 BLOCKED，先给方案，不能添加生产工具或更改上游。

错误分类分开：模型未产工具意图或拒绝 schema=Provider/模型资格；RPC已收但无dispatcher=Runtime；handler error=工具；原生事件存在但无UI=Renderer。先用固定解析/失败/取消L1，再真实L4六环节；取消只读工具可设有界可取消等待的第二测试fixture，不将 sleep 工具进入生产。工具调用记录和会话切换/重启恢复显示不得再次执行handler。

## 6. A-02-03 Native Attachment Pipeline 审计

已继续追踪`server.py:11424` → `agent/context_references.py` preprocess_context_references：文本文件内联正文，binary仅提供路径/类型/大小及工具提示，folder展开目录列表，不递归上传全部内容。`agent/image_routing.py`按auto/native/text选择原始图像content parts或vision_analyze描述；后者主模型只接收有损描述，还可能调用辅助视觉Provider。必须单列辅助endpoint及授权，不能把主模型答对说成主模型收到图片。实际图像预分析链也必须纳入请求ledger，测试配置不得偷偷继承用户辅助Provider。

## 7. A-02-04 Session Persistence 审计

存在两个身份域：Gateway内存runtime id，SessionDB durable stored id/session_key；自动压缩可轮换stored tip，Composer通过lineage root键关联。`store/session.ts` 是活动视图，`session-states.ts` / use-session-state-cache 是每runtime镜像；它们不是消息数据库。Backend SessionDB 的state.db保存会话/消息及tool_calls/tool结果，create有lazy入库语义，未提交空会话不能假定重启后必存在。历史通过HTTP API读取，live恢复通过session.resume；两者真相不可互相替代。

| 数据/状态 | 实际持久化与测试重点 |
|---|---|
| 未发送文本草稿 | store/composer.ts `hermes:composer-drafts:v3` localStorage；会话/lineage作用域；新建不自动清空，跨新建/切换/关闭重启分别验 |
| 未发送附件 | 同文件明确memory-only（blob/upload state）；跨页可在内存保留，重启不承诺；文本恢复不得显示失效的已上传假成功 |
| 已提交/已结束消息 | state.db + 原生历史API；完整role/content/tool_call_id/result/顺序校验；模型默认值与会话override分别恢复 |
| 运行中会话 | live cache/inflight snapshot、turn marker/后端进程状态需分别验；Renderer重启与整个Backend死亡不同；不能把历史消息恢复写成继续执行保证 |
| 错误/中断会话 | 部分消息、error及busy复位；禁止重启后重复模型请求或工具 |

测试至少两合成Session：A草稿/附件、B已结束工具轮；切换时同时A流/B发稿，确保事件与草稿不串；另建错误和运行中样例。记录stored/runtime映射、DB只读快照与原生HTTP历史；不可直接编辑DB伪造恢复PASS。覆盖Renderer刷新、正常关闭重启、Backend意外断开三个恢复情形。正向恢复测试不触碰真实userData。要验证工具历史必须依赖A-02-02；纯草稿/读历史的L0～L2可在A-02-01期间研究，但不能自动开始A-02-04实现。

## 8. A-02-05 Artifact 模型与 Task 缺口

`ArtifactRecord` 实际字段为 id/kind/value/href/label/sessionId/sessionTitle/timestamp，kind为image/file/link。collectArtifactsForSession只扫描assistant/tool消息，也扫描工具参数、JSON结果中的候选路径。id=`session.id + ':' + value`，每会话相同value去重；无独立artifact表/创建事务，无taskId/state/completedAt/error字段。ArtifactsView读取listAllProfileSessions(30,1)，并发取messages后派生；单个messages读取失败会被跳过，不能将显示空列表解释为没有产物，也不能假定全历史覆盖。

1. 身份对同Session、相同规范化value具有派生确定性；不是跨Session/改名/移动仍稳定的全局产物ID。
2. 同Session可派生多个不同value；同value跨消息被合并。
3. 原生记录不能表达跨Task绑定。`server.py`传给run_conversation的task_id常用session_key，并不因此产生Artifact外键。
4. 失败产物无原生生命周期字段，只有消息/工具错误；无法认证“失败产物标记”。
5. 工具参数中的预期输出路径可能先于真正产物完成就被收集，显示条目不等于文件存在或生成完成；这是源码风险，未做运行复现。
6. Session删除后派生入口预期不再扫描该会话，但不意味着文件清除；文件保留/清理策略未获得运行证据。测试可删除一个明确合成Session记录（不是文件批删），用户真实历史禁止操作。
7. 重启可从持久消息重新派生；文件是否仍可访问、图片失败状态是否保留、profile范围/分页是否完整，需要独立验证。

关系应画为 `SessionDB消息 → 派生Artifact引用`；`Task → Artifact` 是明确未证明的目标。Kanban工具有自己的任务/attachments与artifacts通知代码，但未发现与该Desktop ArtifactRecord构成统一关系的证据；不将两套模型合并、不启用自治Kanban来凑验收。

本阶段只认证派生、去重、类型、Session跳转、受控文件存在性、重启和多Session隔离。用A-02-02只读测试工具返回预先由harness创建的合成文件引用，工具不生成文件；另验返回不存在路径/失败结果/运行中参数，观察原生行为。若用户仍要求任务级完成/失败/取消绑定，阶段结论为**原生能力缺口，需另立设计并审批**，不得新增表、第二套store或提前绑定简历/PDF/岗位。
