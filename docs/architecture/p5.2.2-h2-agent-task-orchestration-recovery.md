## 3. Task lifecycle model

业务语义由原字段派生：idle→无业务任务；processing→active且有执行；waiting_for_user/confirmation→原暂停枚举；committed→权威保存回执；completed→GoalCompletionGuard和已完成checkpoint；partial→已有提交但续接/运行未结束；failed/cancelled→错误或停止。Runtime completed本身不证明业务完成。

已完成写入的来源/版本保留在Repository和回执；续接任务另存最小committedPredecessor定位。没有改变正式事实，也不通过模型回答判定保存成功。

## 4. Session recovery

源码根因：Composer初始可发送，发送会设置userInteracted并取消初始恢复；指定Session读取异常被吞后还会选择其他Session。增加工作区恢复状态及发送/附件/快捷动作门禁；initial restoring→ready或new_session_ready，读取失败→failed。原Session缺失不再选择另一个Session；显式新任务仍可创建。恢复包括原Session内Branch/TaskState/实体/确认/续接整体，并以Host采用后的Session为准。异步切换使用原request fence。

组件测试覆盖阻塞早发、恢复同一Session/Branch/Task、读取失败和缺失不新建。唯一Browser也已通过刷新后ready、原Session及相同TaskState断言；随后保存请求的MCP记录仍属于原Session。**原早发跨Session竞态已在该路径关闭**，不等于全部刷新旅程取得资格。

## 7. Stop / Retry / Edit

Stop先持久化原Host中断，原子写入结束后按Repository/Session回读收口；保存完成后暂停不撤销Branch/Revision，未开始的Fit保留可继续动作。拟继续的Host步骤先发布持久checkpoint，避免Stop使用旧Session revision；Stop与CAS交错由回读解决，不降低CAS。

Job Fit续接重试使用持久目标、原操作ID和精确Revision，只执行job_fit；校验来源/Session/实体/当前Branch版本，失败不可重试时不显示重试。重试创建新的Host逻辑Turn，不伪造旧Hermes Run成功。定向测试覆盖失败后重开Host、仅Fit重试、Job/Revision不重复、目标冲突、不可重试、提交后Stop继续及Fit期间Stop。

Edit继续复用活动分支和ownership fence；无前置checkpoint时清除旧Task/proposal/confirmation/continuation，避免拿未来状态续跑。已提交Repository数据不回滚。旧分支/历史仍保留。
