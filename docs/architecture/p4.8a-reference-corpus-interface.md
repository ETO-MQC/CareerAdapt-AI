# P4.8a future reference-corpus interface

This document reserves an integration boundary for future industry-resume
references. P4.8a does not ingest a corpus, train a model, fine-tune a model,
or add a runtime dependency.

## Boundary

The future adapter is read-only and produces a reviewable, non-authoritative
reference pack. It may inform wording patterns and question prioritization,
but it may never create a CareerProfile fact, ResumeBranch item, evidence ref,
or PDF claim by itself.

```ts
type CareerReferenceCorpusRequest = {
  corpusId: string;
  query: string;
  targetRole?: string;
  locale?: string;
  licenseAllowlist: string[];
  excludePersonalData: true;
};

type CareerReferenceCorpusResult = {
  corpusId: string;
  adapterVersion: string;
  rightsStatus: "approved" | "rejected" | "needs_review";
  references: Array<{
    referenceId: string;
    patternType: "question" | "bullet_structure" | "section_order" | "review_rule";
    pattern: string;
    sourceUrl?: string;
    license: string;
  }>;
};
```

## Safety rules

- Rights and license status are checked before a reference is returned.
- Personal data and candidate-specific claims are excluded or redacted.
- References are style/method guidance only; user evidence remains the sole
  authority for facts.
- No reference is copied into a resume as a factual statement.
- The adapter output is ephemeral until a later product decision defines
  auditable storage and retention.

The P4.8a implementation uses only the existing local skill guidance and
deterministic evidence graph. Corpus retrieval remains a future phase.
