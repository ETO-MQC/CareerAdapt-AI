# 生命周期删除隔离 Hotfix

日期：2026-11-09—10。起点 HEAD `944c818`，尚未提交。

## 用户要求与实际范围

删除或移入回收站后，普通页面隐藏、内置 Agent 不读取；覆盖岗位、人物、资料版本及其简历子项。保留回收站管理、显式恢复、备份和历史聊天展示。保留本轮开始时已有的回收隔离审计文件；不扩展 C/V4，不提交、推送或打包。

## 根因和修复

旧实现只在岗位页面过滤回收 ID。Agent 按 ID 查询、去重、工具回执缓存、资料/简历详情及旧会话上下文没有一致生命周期检查，因此已删除岗位仍可被误判为保存成功。人物删除也没有统一约束子资料和简历读取。

- Repository 增加当前可用读接口，检查实体生命周期和人物父级；原始读继续服务回收、备份和历史管理。
- Agent 服务、快捷操作上下文、Host 和生产绑定统一使用可用读。Gateway 在执行前及返回缓存/结果前检查，阻止删除期间的旧回执和内容返回。
- 岗位回收元数据使用事务，防止并发删除覆盖。重新提交相同粘贴 JD 建立新代际岗位，旧岗位、候选及快照保留；重复提交复用新有效记录。
- 资料和简历正式写入口检查父级可用性。归档成功回执只允许返回状态元数据，归档正文仍隔离。
- 数据范围使用既有 appMeta 的不透明哈希，变化后切换 Hermes 会话上下文、清除失效目标/摘要/待确认状态。页面历史消息保留；不再向新的范围重新发送整段页面历史。诊断读取不消费上下文变更标记。
- 普通页面订阅岗位/人物/资料状态，清除不可用版本的显示；本地 Profile 和 Job 覆盖值不能重新引入已删除记录或旧版本。

没有新增表、依赖、事实、Schema v2 或 Fact Guard 阈值变更；没有恢复 Native runtime。
