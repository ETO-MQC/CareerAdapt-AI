## 实际请求观测与能力边界

测试专用本地透明转发器接收原生 AIAgent 的请求，转发到当前配置的 AMD endpoint；不重试、不替换模型、不保存请求头或原始 Base64。它在写证据前把图像换成 MIME、解码长度和 SHA；文本仅来自合成上下文，路径脱敏。Native request dumping 关闭。该架构是隔离测试观测，不是新增生产上传服务。HTTP 200 和外发 payload 只证明图像请求被接口接收，不证明模型内部处理成功。

本地普通文件使用 `file.attach(path)`，Renderer 不需要先读取其完整字节，Gateway 直接读取并暂存；远程普通文件用 `data_url`。图片本地走 `image.attach`，远程走 `image.attach_bytes`。远程分支仅有精确锁定函数/本地受控测试，不能冒充真实远程部署验收。

`context_references.py` 实际把 UTF-8 文本内联到上下文。PDF 等二进制只生成路径、类型、大小和工具读取提示；Files 不会自动调用独立 `pdf.attach` 转换 RPC。PDF 正文理解依赖原生工具链，沿用 `BLOCKED_A02_02_L4`，没有直接调 handler 绕过这一门禁。

文件夹生成最多 200 条的目录列表，不将子文件正文递归上传。存在、空、缺失及“文件当目录”的 L2 情况已检查；不可访问目录未做 ACL 修改，保留未验证。`auto/native/text` 六种能力元数据组合在 L2 决策层通过；只有 native 走了本轮真实 Provider 图片请求。没有运行辅助 Provider 或把描述文本冒充主模型视觉。

URL 与 Prompt Snippets 未取得本轮实际 UI/最终提交证据，不计为二进制上传，也不计入通过项。CSV/其他文档的完整真实入口覆盖仍缺失。

## 真实缺陷及项目内修复

第三轮可靠性测试选择一个不存在的完整 Windows 路径。锁定 Gateway `_resolve_gateway_attachment_path` 复用了 CLI “路径 + 后续文字”解析：完整路径不存在时，按空格拆分后误选了已有的路径前缀文件。实际 ACK 返回文件名 `CareerAdapt`、0 字节，而非预期的 missing-controlled.txt 错误。该零字节文件被复制到本轮隔离 workspace，没有发给 Provider。失败断言保留；不能因为 UI chip 存在就认证附件身份正确。

新增项目虚拟补丁只在 `--careeradapt --attachments` 下为 Windows 盘符路径加双引号，避免把路径后半段当作 prose。补丁校验锁定原文件的规范化 SHA 和唯一 anchor；外部 Runtime 文件不写入。受控 Gateway resolver 证明旧行为会选前缀、修复后缺失路径返回 None、有效含空格路径仍正确；精确修补后的 upload 函数四条本地/远程路由及失败/明确重试通过，Renderer 构建与 Native TS 比较通过。

**修复后的真实 Electron 未复验。**三轮额度已经耗尽，不启动第四轮。该 opt-in 修复是待真实复验的交付，不能称为生产默认修复；UNC 和其他跨平台异常路径也未据此签发资格。
