**整体加载是确定性 NO-GO。** TypeScript AST 提取锁定 SDK 的运行时 export，与原插件的全部静态 SDK imports 对照，缺少且仅缺少 `useTheme`、`requestTheme`。Node VM 仅进行 ESM link（未 evaluate）得到 `SyntaxError: ... does not provide an export named 'requestTheme'`。该失败发生在 register 之前，插件内部 try/catch 无法补救。此检查的 SDK 模块仅提供实际导出名称，用于证明链接契约，不是 Host 实测或兼容层；结果完整嵌入 evidence。

即使以后重新编写移除这两个 import，`ctx.onDispose(...)` 仍会在 L2539 抛错，不能据此声称“修两个 import 就兼容”。当前报告只分析这一后续断点，不执行修改版。

## 5. CareerAdapt 主题适配与文档隔离

实际链：`poc/profile-packaging/ProfileHostAdapter.tsx` → `poc/profile-plugin/ProfileCareerView.tsx` → `profile.css`。未连接真实 Profile。

- ProfileCareerView 是纯展示；CSS 全部限定 `.ca-profile-poc`，由 React `<style>` 持有。这一边界可以保留。
- `--foreground`/`--background` 是锁定 Host styles.css L424–425 的真实 alias，分别指向 `--dt-foreground`/`--dt-background`。前景/背景可随明暗和主题自动更新，无需 useTheme。
- `--border` 在锁定 Host src 未找到定义，Host 使用 `--dt-border`/`--ui-stroke-*`。当前两处分隔线会落到硬编码 `#888`。`#242424`、`#faf9f7` 是前景/背景 fallback，不是所有 Host 状态下生效的固定颜色；不应把整个 PoC 误报为完全硬编码。
- `font:14px/1.6 system-ui,sans-serif` 不跟随 `--dt-font-sans`；color-scheme:light dark 不会主动切主题。文字 opacity=.75 的最终对比度需要后续实测，不能用既有暗色截图证明所有 palette 可访问性。
- Adapter 外层刷新按钮和 loading/error 文案没有自身语义类，仍依赖 Host/UA 默认；PoC 有暗色截图和生命周期证据，但没有完整外观系统/各状态 token 验收。本轮只记录，不修复。

独立语义色有必要：职业产品的错误、警告、事实确认、评分不能只用品牌 accent 或红绿表达。它们是业务 UI 的语义，不能更改 Fact Guard/评分含义，也不能写进简历模板。Host 没有足够公开语义 token 时先明确待设计，不做猜测 API 的 wrapper。

三类外观责任：

1. **全局应用外观**：Hermes 拥有主题/明暗/系统模式、原生窗口、缩放、聊天行为与全局设置持久化。Career 插件只消费已应用 token，可贡献经过审查的数据主题；通过 Host 自有 UI 选主题。
2. **CareerAdapt 业务外观**：Career 拥有 `.careeradapt-*` 根容器、语义 token、布局、表单/列表/空态。无需维护第二个全局 ThemeProvider；自身偏好才用 ctx.storage。不要以“主题扩展”为名改变真实数据与权限边界。
3. **简历文档模板**：由 Resume Schema v2 派生的 renderModel、presentationConfig 与 `--resume-*` 决定。纸面颜色、字体、字号、间距、分页与导出配置独立，不继承 --ca-* 或 Host 字体。

## 6. 三方案比较与推荐

| 维度 | A 直接适配 Appearance Hub | B Fork 为第一方外观插件 | C 公开 SDK 的 Career Appearance Layer |
| --- | --- | --- | --- |
| SDK 兼容性 | 当前两缺失 import 与 onDispose 阻断；完整功能无法保留 | 只保留贡献/自有 UI 可兼容，大量功能需删去/重写 | 与锁定契约一致；缺失能力明确 UNSUPPORTED |
| 维护成本 | 高：跟进其 fallback/内部变化 | 中高：负责 fork、安全清理和双向合并 | 初始语义设计中等；长期边界小且清晰 |
| 上游升级影响 | 高度耦合 Hub 和 Host 内部变化 | 可控制但需持续筛选合并 | 仅跟踪公开 SDK/token 契约，固定版本验证 |
| 全局主题一致性 | 第二入口同步依赖 B/F/E | 删私有链后可统一，但不能保留完整面板 | 由 Host 单一权威，Career 自动消费 |
| 安全边界 | 同源全局写/私有 IPC/内部 atom，不可接受 | 可清除，必须逐项证明；fork 不自动授信 | 自身命名空间/React 生命周期，最小触面 |
| UI 自定义 | 表面多，实际绑定 Host DOM | 可定制保留子集 | Career 组件可充分自定义；原生窗口能力仍归 Host |
| 用户体验 | 当前不可加载；大量设置与 Host 重复 | 可精简，但原生高级控制缺失 | 统一外观与业务语义，避免两份全局设置 |
| 长期维护性 | 差 | 中 | 最佳，符合 Hermes Host + Career UI 方向 |
| 决策 | NO-GO | 不推荐当前立项；极小 palette-only fork 可另议 | **推荐；仅设计方向 GO，实施待用户审核** |

选择 C：借鉴 Ink & Paper 的中性层级、语义分离和暖纸可选方向；使用公开主题贡献与 Host 组件；不为了复用 146680 字节插件而保留 OFFICIAL_CHANNEL、全局键迁移、Native Bridge、DOM 仲裁与无效生命周期。C 不承诺在 Career 面板切换全局主题；该能力在锁定 SDK 中就是 UNSUPPORTED。保留 Host 自有主题选择 UI 即可达成自动适配，不要求升级/Core 修改。
