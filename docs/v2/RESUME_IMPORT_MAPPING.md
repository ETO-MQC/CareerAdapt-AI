# 简历导入解析与字段映射

## 当前实现

导入不会直接修改正式简历，统一经过以下链路：

1. PDF 使用 PDF.js 读取文本层；DOCX 在浏览器中提取正文；JSON 先通过 `StructuredResumeDraftSchema`。
2. 文本清理后按页保存来源记录，并用标题词典、联系方式正则、项目符号和空行规则划分基本信息、概述、经历、技能、证书等栏目。
3. 每一项生成来源页、原文片段、栏目类型、置信度和是否默认包含，形成 `ImportedResumeDraft`。
4. 用户在核对页修改、拆分、合并、改栏目或排除内容。
5. 只有用户确认的内容才通过 Repository 写入正式 `CareerProfile` 与通用 `ResumeBranch`，并创建版本记录。

这是一套可解释的确定性规则，不是视觉版面理解或通用语义模型。它适合标准单栏、存在正常文本层且栏目标题常见的简历。

## 为什么会零命中

- PDF 是扫描图片，没有文本层。
- 字体编码异常，复制出的文字为空或乱码。
- 双栏 PDF 的文本读取顺序交错，标题与内容不再相邻。
- 栏目名称不在当前词典中，或标题与正文处于同一行。
- 内容主要放在表格、文本框、图标或装饰性布局中。

因此“PDF 能打开”不等于“PDF 有可解析文本”。当前 OCR 入口只是实验适配层，运行环境尚未安装正式本地识别引擎；既有基准也未通过双栏阅读顺序要求。

## 目标算法

正式方案应拆为四层，而不是让一个正则或一次 AI 调用完成全部工作：

1. 版面恢复：读取文本块坐标或 OCR 坐标，识别栏、行、标题和阅读顺序。
2. 栏目识别：结合标题词典、字号/位置、日期密度和上下文识别栏目边界。
3. 字段映射：对姓名、联系方式、组织、角色、学校、专业、日期和描述生成候选，并计算置信度。
4. 人工核对：高置信度预选，低置信度明确标记，未定位内容不自动进入正式数据。

评估必须使用真实单栏、双栏、表格、扫描和中英文样本，至少记录字段级 precision/recall、阅读顺序正确率、零命中率与用户平均修订量。正式 OCR 接入仍需单独确认引擎、中文模型体积、Worker 性能和隐私边界。
