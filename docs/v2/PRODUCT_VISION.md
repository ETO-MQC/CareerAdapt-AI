# V2 Product Vision

## 第一代解决的问题

V1证明了“职业母档案 -> 岗位理解 -> 证据匹配 -> 可解释建议 -> 事实安全 -> 岗位分支 -> 模板预览 -> PDF导出”的纵向闭环可运行。它最有价值的能力不是模板，而是事实来源、岗位证据映射、Fact Guard和多岗位分支。

## 第一代不足

V1仍像一个流程型工作台：用户可以生成分支和预览，但不能在预览中自然地选择、编辑、排序、调样式。模板只有两套，导出依赖浏览器打印，多Profile和Application尚未显式化。对用户来说，“成品简历能不能像简历编辑器一样顺手改、像正式模板一样好看、像PDF一样稳定导出”会直接决定产品感知。

## 第二代一句话价值主张

将用户已有简历、职业事实和岗位要求转化为可直接编辑、可切换正式模板、可针对岗位定制并稳定导出的智能简历工作台。

## 核心用户

- 第一次求职、需要快速做出正式简历的大学生。
- 已有旧简历、希望导入后换模板并修表达的用户。
- 多方向投递、需要不同岗位简历分支的用户。
- 不擅长排版、但需要稳定导出PDF的用户。
- 担心AI编造事实、需要来源和确认机制的用户。

## 核心流程

```text
导入/粘贴简历
-> 提取内容和来源
-> 写入CareerProfile与ResumeDocument
-> 打开Resume Studio
-> 单击选中、双击编辑、拖动排序
-> 右侧属性面板调整样式
-> 切换正式模板
-> 粘贴岗位JD并获得区块级建议
-> 接受/拒绝/编辑建议
-> Fact Guard和排版检查
-> PDF直接下载或打印fallback
```

## 为什么不能只是更多模板

模板数量只能改善第一眼观感，不能解决“内容怎么改、改完是否真实、导出是否稳定、不同岗位如何复用”的核心问题。V2模板中心必须服务于Resume Studio：模板只控制视觉，不能生成事实，也不能吞掉用户内容。

## 为什么不能先只做Application看板

Application看板能管理岗位状态，但用户最重视的痛点仍是把一份真实经历做成可投递的正式简历。若前几个Sprint都围绕看板，产品会偏离“导入、编辑、模板、岗位定制、导出”的主线。

## 成功指标

- 用户可在预览中直接完成一条经历的编辑并保存。
- 编辑后预览同步错误数为0。
- 样式操作修改事实数为0。
- 模板切换丢失内容数为0。
- PDF导出裁切或中文不可复制问题显著减少。
- 岗位建议仍保持 `unsafeAllowed=0`。

## 第二代非目标

第一阶段不做任意PDF一比一还原、不做完整自由画布、不做自动投递、不做复杂云同步、不做模板市场、不做付费系统、不从零重写V1稳定模块。

## 3个月目标

完成Resume Studio基础、可视化编辑、第一批正式模板、PDF直接下载方案、区块级岗位建议和基础排版诊断。

## 6个月目标

扩展DOCX导入导出、样式近似映射、多Profile与Application、申请材料包、面试准备，并保持事实安全和迁移可回滚。
